# 风格匹配路由 v2.2

## 核心设计哲学

**v1.0 的问题**：19 行静态匹配规则 → 匹配不到走兜底 → 用户无感。"兜底"的意思是"我不知道最好的答案，给你一个不出错的答案"。不出错的答案永远不会让用户兴奋。

**v2.0 的原则**：

```
规则不是引擎，是护栏。
AI 不是兜底，是引擎。
知识库不是真理，是缓存。
兜底不存在——每次都是一次发现。
```

**v2.1 的关键升级**：

```
v2.0：规则先画圈 → AI 在圈内搜索 → 用户看到"安全但平庸"的推荐
v2.1：AI 先看世界 → 规则后标注可执行性 → 用户看到"全局最优 + 诚实评估"

规则的角色从"匹配前的过滤器"变成"匹配后的翻译官"：
  光线路由器不再说"顺光→排除逆光通透"
  改为说"逆光通透需要逆光→🟡 可用地面反射模拟，效果约 70%"
  
  设备约束不再说"无长焦→排除空间压缩"
  改为说"空间压缩需要长焦→🟡 用 2× 裁切+靠近主体替代，效果约 60%"
  
  缓存从"审核者"降为"加速器"——新发现和已验证匹配权重平等

用户最终选的还是"现在就拍"那个能执行的方案。
但 AI 的自由搜索保证了这个方案是全局最优，
而不只是"规则没杀死的里面最好的那个"。
```

## 一、新架构 v2.1

> **v2.1 核心变更：AI 先自由搜索 → 规则后诚实标注。规则不再在匹配阶段杀可能性。**

```
┌─────────────────────────────────────────────────────────────┐
│                    🧠 AI 引擎层（先跑，不受限）                 │
│                                                              │
│  场景输入 → AI 理解场景独特美学潜力                            │
│          → AI 在开放世界搜索全球最佳风格（无预过滤）             │
│          → AI 生成创意方案                                    │
│          → AI 发现知识空白并主动填补                           │
│                                                              │
│                    ↓ 发现完成                                 │
│                                                              │
│  🏷️ 规则标注层（后跑，只标注不排除）                           │
│  ├─ 光线匹配度：🟢完美 / 🟡可模拟(效果约X%) / 🔴需等待        │
│  ├─ 设备可执行性：🟢直接拍 / 🟡微调 / 🟠替代方案              │
│  └─ 安全红线：危险机位 → 唯一的一票否决                        │
│                                                              │
│                    ↓ 结果沉淀                                 │
│                                                              │
│  📚 知识缓存层（纯加速——不限制新发现）                         │
│  ├─ 已有风格 → 快速通道（已验证 N 次）                         │
│  ├─ 新发现风格 → 自动注册（与已验证权重平等）                   │
│  └─ 验证计数 → 越多验证越优先推荐（但新发现也可直接进入推荐）    │
└─────────────────────────────────────────────────────────────┘
```

## 二、匹配流程 v2.1

### 完整流程（4 步）

```
Step 1: 场景美学理解（不做排除，只做理解）
  ├─ 豆包视觉识别的完整场景描述
  ├─ 题材类型检测（人像/风光/静物/街拍）
  ├─ 设备能力档案加载（硬约束 + 设备优势——用于后续标注，不用于过滤）
  └─ 输出：场景美学一句话描述 + 题材 + 设备档案

Step 2: AI 自由搜索发现 — 主匹配 🆕 v2.1
  ├─ ⚠️ 关键变更：此步骤不再接收预过滤后的"安全候选池"
  │   AI 在开放世界中自由搜索——看到所有可能性
  ├─ 场景美学提炼：一句话描述这个场景最动人的潜质
  ├─ 多源搜索：
  │   ├─ WebSearch × 3-5："{场景描述} photography style best lighting composition"
  │   ├─ WebSearch × 2："{场景描述} 摄影 风格 拍摄技巧"
  │   └─ WebSearch × 1："{类似场景} {类似光线} photographer reference"
  ├─ AI 综合判断：基于搜索结果 + 场景洞察，推荐 3-5 个最佳风格方向
  └─ 每个推荐附带：为什么适合 / 参考作品 / 全局最优判断

Step 3: 规则诚实标注 🆕 v2.1
  ├─ ⚠️ 关键变更：此步骤不排除风格——只为每个 AI 发现的风格标注可执行性
  ├─ 光线匹配度标注：
  │   ├─ 🟢完美：当前光线与风格需求天然匹配（如多云柔光→森系）
  │   ├─ 🟡可模拟：光线不完全匹配但可通过调整模拟（如顺光→利用地面反射模拟逆光通透）
  │   └─ 🔴需等待：光线完全不匹配，但换个时段可以（如正午硬光→蓝调时刻拍电影感）
  ├─ 设备可执行性标注：
  │   ├─ 🟢直接拍：设备天然支持（如手机最近对焦距离近→微距风格）
  │   ├─ 🟡微调：需要 1-2 步调整（如 2× 裁切替代长焦）
  │   └─ 🟠替代方案：需要替代方案但可理解原理（如无长焦→用 0.5× 低角度仰拍替代空间压缩）
  ├─ 安全红线检查：危险机位 → 一票否决（唯一的硬排除）
  └─ 输出：每个 AI 发现的风格 + 诚实标注（🟢🟡🔴🟠）+ 替代方案（如有）

Step 4: 知识缓存对比 + 输出匹配结果
  ├─ AI 推荐 ∩ 知识库已有风格 → ✅ 直接使用（快速通道）
  │   标记验证计数 +1
  ├─ AI 推荐 - 知识库已有风格 → 🆕 新发现！
  │   ├─ 质量评估通过 → 采纳推荐，自动注册到缓存表（与已验证权重平等）
  │   └─ 质量不足 → 保留在备选列表，不进入主推荐
  ├─ AI 推荐包含已有风格的变体 → 🔄 变体发现
  │   标记为已有风格的 sub-type，记录触发场景
  └─ 输出：
      ├─ primary: 全局最优推荐 + 诚实标注
      ├─ alternatives: 2-3 个备选方向 + 诚实标注
      ├─ discoveries: 新发现（如有）
      └─ safety_excluded: 仅列出安全红线排除的（如有）
```

### 关键变化 v2.1：规则从"排除"变"标注"

```
v1.0：
  题材+光线+情绪组合不在表中 → 参照最接近行 → 标记"风格手动匹配"
  结果：用户看到一个"还行"的推荐，没有惊喜

v2.0：
  场景不在知识缓存中 → AI 主动搜索发现 →
  ├─ 找到了更好的匹配 → 给用户惊喜 + 入库
  └─ 确认知识库中的最佳匹配仍然是全局最佳 → 给用户解释为什么
  结果：用户要么得到惊喜，要么得到"这个确实最适合你"的确定性
  
  但问题：AI 搜索前被规则预过滤——搜不到"逆光通透"因为光线是顺光就排除了

v2.1：
  场景不在知识缓存中 → AI 在开放世界自由搜索（无预过滤）→
  ├─ 找到了最佳匹配（可能是逆光通透，虽然当前是顺光）→ 
  │   ├─ 标注"🟡 当前顺光——可利用地面反射模拟逆光，效果约 70%"
  │   └─ 用户看到全局最优 + 诚实评估
  ├─ 确认缓存中的最佳匹配仍然是全局最佳 → 给用户解释为什么
  └─ 安全红线（危险机位）→ 唯一硬排除
  结果：用户始终看到这个场景的全局最优解
```

## 三、知识缓存层（原"路由规则表"降级）

### 3.1 缓存的定位

以下匹配表**不是真理，是经过验证的历史最佳实践**。它的作用是：

1. **加速**：已验证的匹配直接使用，不需要每次都搜索
2. **验证**：每条匹配记录验证次数，高验证=高置信度
3. **可更新**：AI 发现更好的匹配时，更新此表

### 🆕 3.1.5 引用规范 v2.2

**风格引用必须使用 one_liner**：缓存表中命中的风格，输出时必须引用 `style-recipes/_index.md` 中定义的 one_liner 作为权威描述，而非缓存行中的简写。

```
缓存表中存的是：森系（简写）
输出时引用的是：森系——在森林里待久了，身上沾了树叶和泥土的气息（one_liner）
```

**情绪引用必须查 mood-lexicon 完整视觉翻译**：缓存表中"情绪"列使用压缩标签（如"温暖+松弛"）仅用于快速索引。当缓存命中时，AI 必须读取 `mood-lexicon/` 对应条目的完整 8 维视觉翻译，而非仅使用标签名做匹配判断。

```
压缩标签（缓存表）：温暖+松弛
    ↓ 命中后必须查
完整视觉翻译（mood-lexicon）：暖色偏移 + 软光 + 低光比(≤1:4) + 低对比 + 大留白(≥30%) + 中景亲密距离 + 不看镜头/互动 + 低饱和度
```

**v2.1→v2.2 核心变化**：风格引用从各文件自描述升级为 one_liner 统一标识；情绪标签从 2D 压缩标签升级为 mood-lexicon 完整视觉翻译的必查引用。

### 3.3 缓存命中分级体系 v2.2 🆕

> **v2.2 关键升级：从布尔判断（命中/未命中）升级为四级梯度（S/A/B/C）。每一级对应不同的搜索深度和 AI 介入程度。**

#### 3.3.1 三维匹配规则

缓存表中每行有三个匹配维度。匹配判定不是"是/否"——每个维度有三种状态：

**题材匹配**（权重 20%）：

| 状态 | 判定 | 示例 |
|------|:--:|------|
| ✅ 完全一致 | 缓存行题材 = 当前题材 | 人像=人像，静物=静物 |
| ⚠️ 相近 | 主体类型相同但场景不同 | 人像→街拍（都有明确人物）|
| ❌ 不同 | 主体类型不同 | 人像→静物 |

**光线匹配**（权重 50%——最关键，决定什么风格可用）：

| 状态 | 判定 | 示例 |
|------|:--:|------|
| ✅ 完全一致 | 光质+方向+特殊条件全部匹配 | 户外软光=户外软光 |
| ⚠️ 同大类 | 光质相同，方向或子条件不同 | 户外硬光+树荫 ≈ 户外硬光（树荫是子条件）|
| ⚠️ 可类比 | 光质相近，环境不同 | 窗边侧光 ≈ 户外侧光（方向相同）|
| ❌ 相反 | 光质相反 | 户外硬光 ≠ 户外软光，顺光 ≠ 逆光 |

**情绪匹配**（权重 30%——决定审美方向）：

| 状态 | 判定 | 示例 |
|------|:--:|------|
| ✅ 高度一致 | 核心情绪重叠 ≥ 2 个关键词 | 闲适+松弛 ≈ 松弛+温暖 |
| ⚠️ 部分一致 | 核心情绪重叠 1 个 | 闲适+清爽 ≈ 松弛+清爽 |
| ❌ 不一致 | 无重叠关键词 | 闲适+松弛 ≠ 孤独+疏离 |

#### 3.3.2 四级命中

| 等级 | 条件 | 搜索深度 | WebSearch | 动作 |
|:--:|------|:--:|:--:|------|
| **S** | 三维全中（光线✅ + 题材✅ + 情绪✅）+ 验证 ≥ 3 | 零搜索 | 0 次 | 秒出——缓存结果即最终结果。不调用 WebSearch |
| **A** | 三维全中 + 验证 1-2 | 确认搜索 | 1-2 次 | 缓存结果直接进入推荐候选，轻量搜索确认"是否有更好的新发现"。如搜索结果与缓存一致 → 验证+1 → 升 S |
| **B** | 二维命中（含光线✅/⚠️）+ 一维相近 | 中度搜索 | 3-4 次 | 缓存结果作为"已知参考"参与判断。AI 搜索确认后综合决策。搜索结果支持缓存 → 验证+1；搜索结果有新发现 → 新发现与缓存平等 |
| **C** | 光线❌ 或 二维以下命中 | 深度搜索 | 5-7 次 | 缓存无有效参考。AI 在开放世界深度搜索。找到后自动注册到缓存表 |
| **脑洞** | 用户主动选"✨ 脑洞大开" | 广度搜索 | 不限 | 不限于可执行性，搜创意/大师/跨媒介。不依赖缓存 |

#### 3.3.3 判定流程

```
当前场景 → 提取三维特征（题材/光线/情绪）
    │
    ▼
扫描缓存表每一行 → 计算匹配度：
    │
    ├─ 光线：完全一致=2分，同大类=1.5分，可类比=1分，相反=0分
    ├─ 题材：完全一致=1分，相近=0.5分，不同=0分
    └─ 情绪：高度一致=1.5分，部分一致=1分，不一致=0分
    │
    ▼
取最高分的那行：
    总分 ≥ 4.5 → S/A 级（取决于验证次数）
    总分 3.0-4.4 → B 级
    总分 < 3.0 → C 级
    无任何行 ≥ 1.0 → C 级（首次遇到的场景类型）
    │
    ▼
按等级决定搜索深度 → 执行搜索 → 输出结果 + 自动注册
```

#### 3.3.4 命中率演进

缓存是活的——用得越多，命中率越高：

| 使用量 | 缓存行数 | S/A 命中率 | B 命中率 | C 命中率 | 平均 WebSearch |
|:--:|:--:|:--:|:--:|:--:|:--:|
| 初始（24 行）| 24 | ~5% | ~15% | ~80% | ~6 次 |
| 100 次后 | ~80 | ~15% | ~30% | ~55% | ~4.5 次 |
| 500 次后 | ~200 | ~30% | ~40% | ~30% | ~3 次 |
| 成熟期 | ~500+ | ~50% | ~35% | ~15% | ~1.5 次 |

> **核心逻辑**：用得越多 → 缓存越密 → 命中率越高 → WebSearch 越少 → 越快越省钱。**知识库是活的。**

## 四、AI 搜索发现指南

### 4.1 搜索触发条件（v2.2 更新）

搜索深度由缓存命中等级决定，不再手动判断：

| 命中等级 | 触发 | 搜索深度 | WebSearch 次数 |
|------|:--:|------|:--:|
| S | 🚫 跳过 | 零搜索 | 0 |
| A | ✅ 确认搜索 | 1-2 次，确认是否有更好的新发现 | 1-2 |
| B | ✅ 中度搜索 | 3-4 次，综合决策 | 3-4 |
| C | ✅ 深度搜索 | 5-7 次，开放世界发现 + 新注册 | 5-7 |
| 脑洞大开 | ✅ 广度搜索 | 不限，搜创意/大师/跨媒介 | 不限 |

### 4.2 搜索策略 v2.4

> **v2.4 核心变更：搜索从"5-7路全搜"改为"优先级分层+条件触发"。不是每个场景都需要搜7次——大多数场景3-4路即可。**

#### 优先级分层

```
第一梯队（必搜——信息密度最高）：

  #1: "{场景一句精准描述} {光线特征} photography style inspiration best approach"
      → 目标：全球范围内的风格参考，覆盖面最广
      → 中英文各搜一次（关键词不同）

  #6: "{地点名} {题材} 最佳拍摄方式 {光线特征}"  ← 有GPS时必搜
      → 目标：这个具体地点的最佳拍法——让搜索从"这类场景"变成"这个具体地方"


第二梯队（有明确触发条件才搜）：

  #2: "{题材} {光线条件} photography technique composition 中文"
      → 目标：中文社区操作经验
      → 触发：缓存命中等级 ≤ B 时搜索

  #3: "{标志性场景元素} photographer portfolio reference style"
      → 目标：找到拍过类似元素的摄影师
      → 触发：仅当场景中有标志性元素（古塔/雪道/连廊/球馆/拱门等）
      → 普通河岸/普通客厅/普通街道 → 跳过（搜不到好东西）


第三梯队（场景特定，默认不搜）：

  #4: "{场景} {设备类型} mobile photography creative technique"
      → 触发：仅当设备有特殊约束或优势时
      → 例：前置摄像头自拍 / 仅0.5×+1×无长焦 / 折叠屏特殊角度

  #5: "{场景} {光线} editorial fashion photography style"
      → 触发：仅当 people≥1 且场景有控光潜力时
      → 普通户外随手拍 → 跳过

  #7: "{地点名} {popular_styles} photography"  ← 有GPS+流行风格时
      → 触发：仅当位置丰富度=高且当地有明确的流行风格
```

实际执行时：
- S级命中 → 0次搜索
- A级命中 → 1-2次（仅第一梯队）
- B级命中 → 3-4次（第一+第二梯队中触发的）
- C级命中 → 4-5次（全梯队中触发的，不是固定7次）

#### 来源权重 v2.4

搜索结果的质量不等——AI综合判断时需考虑来源权威度：

```
🏋️ 高权重（引用信心高——可在方案中引用来源）：
  - 专业摄影教程/杂志（fstoppers/DPReview/Photography Life等）
  - 摄影师个人作品集/画廊档案
  - 社交平台高粉博主（小红书/Instagram ≥10万粉）分享的拍摄教程
  - 高赞高收藏帖子（≥5000赞或收藏）← 大众审美验证

⚖️ 中权重（作灵感方向，谨慎引用来源）：
  - 普通社交帖子（<5000赞）
  - YouTube摄影教程
  - 知乎摄影话题回答

📎 低权重（仅作灵感方向，不在方案中引用来源）：
  - 内容农场 / 疑似AI生成内容
  - 泛泛的"N个技巧"列表文章
```

权重不影响是否使用搜索结果的风格方向——只决定方案中是否引用来源名。

#### 诚实机制 v2.4

```
搜索质量自检（在 Step 3 标注前执行）：

每路搜索标注：
  🟢 = 返回具体、可操作、场景相关的信息
  🟡 = 有相关信息但不够具体或相关性一般
  🔴 = 无结果/完全无关/全是低质量内容

综合判断：
  ≥2路🟢 → 正常流程，搜索结果作为主驱动
  全部🟡 → 缩减推荐数量（2-3个），以场景特征分析为主、搜索为辅
  全部🔴 → 诚实告知用户：
    - 不编造"AI发现"的风格
    - 只输出基于场景特征+摄影原理的规则匹配结果
    - 阶段2洞察卡片下方标注：
      > 这次主要基于场景特征分析——没搜到这个场景的公开参考。
      > 下面的方向来自摄影原理，不是网络热门。
```

### 4.3 AI 综合判断框架 v2.4

> **v2.4 变更**：本模块的输出现在与审美主张引擎合并为一次统一的 LLM 推理过程。不再独立产出 `scene_insight`——洞察由统一的 AI 引擎在场景沉浸阶段产出。本模块聚焦于风格发现和标注。

搜索完成后，输出发现的风格（不做排除，不产出独立的 `scene_insight`）：

## 五、自动知识沉淀 🆕

### 5.1 发现驱动的采集

v1.0：知识空白 → 兜底 → 用户无感 → 永远不补
v2.0：知识空白 → AI 搜索 → 找到答案 → 自动入库 → 下次秒出

```
每次方案生成都是一次知识发现机会：

方案生成完毕 →
  ├─ 检查方案中使用的风格匹配关系
  │   ├─ 在 style-router 缓存表中？ → 验证计数 +1
  │   └─ 不在缓存表中？ → 🆕 自动注册
  │
  ├─ 检查方案中产生的风格变体
  │   ├─ 如"清冷森系"是从"森系"变体而来
  │   ├─ 变体参数已在方案中明确（色温-15/绿色往青调等）
  │   └─ → 🆕 自动注册为风格变体
  │
  ├─ 检查方案中引用的大师视角
  │   ├─ 如"川内伦子 × 河边人像"这个组合
  │   └─ → 🆕 注册到 master-router 的场景匹配
  │
  └─ 输出变更摘要（静默，不打断用户体验）
```

### 5.2 轻量采集 vs 完整采集

| | 轻量采集（自动） | 完整采集（手动 /zhichu-collect） |
|---|---|---|
| 触发 | 方案生成时自动 | 用户主动调用 |
| 搜索 | 利用方案生成时的搜索结果 | 全新 Phase 1 多源搜索 |
| 参数提取 | AI 从方案中提取 | 完整 Phase 2 结构化分析 |
| 注册 | 写入缓存表 + 标记 `discovered` | 完整 Phase 4 全文件注册 |
| 置信度 | medium（需后续验证） | high（经过完整流程） |
| 用户感知 | 无感知（后台自动） | 有感知（输出变更摘要） |

## 六、全量发现原则 v2.3

> **v2.3 术语修正**：本模块不再使用"排除/不排除"措辞。本模块的职责是**全量发现**——在开放世界中找到所有可能的风格，只做标注不做减法。风格的去留由下游模块（审美主张引擎 → 方向选择器）在后续阶段决定。

| 发现情况 | 处理 | 优先级 |
|------|------|:--:|
| 危险机位 | **硬删除**——安全是唯一红线。从全局候选池中移除 | 最高 |
| 光线物理不完全匹配 | **诚实标注**——🟢完美/🟡可模拟(标注效果%)/🔴需等待。保留在候选池中 | 标注优先 |
| 设备不完全匹配 | **诚实标注**——🟢直接拍/🟡微调/🟠替代方案(标注效果%)。保留在候选池中 | 标注优先 |
| AI 推荐与缓存不一致 | **AI 优先**——缓存是历史，AI 搜索是现在。但标记差异供后续验证 | AI > 缓存 |
| AI 推荐存在争议（搜索结果不一） | 标记 `contested`，同时呈现多个方向让用户选。保留在候选池中 | — |
| 审美冲突（如暖情绪+冷色调推荐） | **保留在候选池中**——冷色调+暖情绪可以是复合情绪的高级表达。由审美主张引擎判断 | — |

> ⚠️ **重要**：本模块输出的 `annotated_not_ranked`（标注但未进入主推荐）风格**不会被删除**。它们完整保留在全局候选池中，传递给审美主张引擎和方向选择器。一个在当前光线下被标注为 🔴 的风格，可能在 ✨脑洞大开 中被选中——因为脑洞大开不限条件。
