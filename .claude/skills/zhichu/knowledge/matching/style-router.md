# 风格匹配路由 v2.0

## 核心设计哲学

**v1.0 的问题**：19 行静态匹配规则 → 匹配不到走兜底 → 用户无感。"兜底"的意思是"我不知道最好的答案，给你一个不出错的答案"。不出错的答案永远不会让用户兴奋。

**v2.0 的原则**：

```
规则不是引擎，是护栏。
AI 不是兜底，是引擎。
知识库不是真理，是缓存。
兜底不存在——每次都是一次发现。
```

**v2.1 的关键升级**：

```
v2.0：规则先画圈 → AI 在圈内搜索 → 用户看到"安全但平庸"的推荐
v2.1：AI 先看世界 → 规则后标注可执行性 → 用户看到"全局最优 + 诚实评估"

规则的角色从"匹配前的过滤器"变成"匹配后的翻译官"：
  光线路由器不再说"顺光→排除逆光通透"
  改为说"逆光通透需要逆光→🟡 可用地面反射模拟，效果约 70%"
  
  设备约束不再说"无长焦→排除空间压缩"
  改为说"空间压缩需要长焦→🟡 用 2× 裁切+靠近主体替代，效果约 60%"
  
  缓存从"审核者"降为"加速器"——新发现和已验证匹配权重平等

用户最终选的还是"现在就拍"那个能执行的方案。
但 AI 的自由搜索保证了这个方案是全局最优，
而不只是"规则没杀死的里面最好的那个"。
```

## 一、新架构 v2.1

> **v2.1 核心变更：AI 先自由搜索 → 规则后诚实标注。规则不再在匹配阶段杀可能性。**

```
┌─────────────────────────────────────────────────────────────┐
│                    🧠 AI 引擎层（先跑，不受限）                 │
│                                                              │
│  场景输入 → AI 理解场景独特美学潜力                            │
│          → AI 在开放世界搜索全球最佳风格（无预过滤）             │
│          → AI 生成创意方案                                    │
│          → AI 发现知识空白并主动填补                           │
│                                                              │
│                    ↓ 发现完成                                 │
│                                                              │
│  🏷️ 规则标注层（后跑，只标注不排除）                           │
│  ├─ 光线匹配度：🟢完美 / 🟡可模拟(效果约X%) / 🔴需等待        │
│  ├─ 设备可执行性：🟢直接拍 / 🟡微调 / 🟠替代方案              │
│  └─ 安全红线：危险机位 → 唯一的一票否决                        │
│                                                              │
│                    ↓ 结果沉淀                                 │
│                                                              │
│  📚 知识缓存层（纯加速——不限制新发现）                         │
│  ├─ 已有风格 → 快速通道（已验证 N 次）                         │
│  ├─ 新发现风格 → 自动注册（与已验证权重平等）                   │
│  └─ 验证计数 → 越多验证越优先推荐（但新发现也可直接进入推荐）    │
└─────────────────────────────────────────────────────────────┘
```

## 二、匹配流程 v2.1

### 完整流程（4 步）

```
Step 1: 场景美学理解（不做排除，只做理解）
  ├─ 豆包视觉识别的完整场景描述
  ├─ 题材类型检测（人像/风光/静物/街拍）
  ├─ 设备能力档案加载（硬约束 + 设备优势——用于后续标注，不用于过滤）
  └─ 输出：场景美学一句话描述 + 题材 + 设备档案

Step 2: AI 自由搜索发现 — 主匹配 🆕 v2.1
  ├─ ⚠️ 关键变更：此步骤不再接收预过滤后的"安全候选池"
  │   AI 在开放世界中自由搜索——看到所有可能性
  ├─ 场景美学提炼：一句话描述这个场景最动人的潜质
  ├─ 多源搜索：
  │   ├─ WebSearch × 3-5："{场景描述} photography style best lighting composition"
  │   ├─ WebSearch × 2："{场景描述} 摄影 风格 拍摄技巧"
  │   └─ WebSearch × 1："{类似场景} {类似光线} photographer reference"
  ├─ AI 综合判断：基于搜索结果 + 场景洞察，推荐 3-5 个最佳风格方向
  └─ 每个推荐附带：为什么适合 / 参考作品 / 全局最优判断

Step 3: 规则诚实标注 🆕 v2.1
  ├─ ⚠️ 关键变更：此步骤不排除风格——只为每个 AI 发现的风格标注可执行性
  ├─ 光线匹配度标注：
  │   ├─ 🟢完美：当前光线与风格需求天然匹配（如多云柔光→森系）
  │   ├─ 🟡可模拟：光线不完全匹配但可通过调整模拟（如顺光→利用地面反射模拟逆光通透）
  │   └─ 🔴需等待：光线完全不匹配，但换个时段可以（如正午硬光→蓝调时刻拍电影感）
  ├─ 设备可执行性标注：
  │   ├─ 🟢直接拍：设备天然支持（如手机最近对焦距离近→微距风格）
  │   ├─ 🟡微调：需要 1-2 步调整（如 2× 裁切替代长焦）
  │   └─ 🟠替代方案：需要替代方案但可理解原理（如无长焦→用 0.5× 低角度仰拍替代空间压缩）
  ├─ 安全红线检查：危险机位 → 一票否决（唯一的硬排除）
  └─ 输出：每个 AI 发现的风格 + 诚实标注（🟢🟡🔴🟠）+ 替代方案（如有）

Step 4: 知识缓存对比 + 输出匹配结果
  ├─ AI 推荐 ∩ 知识库已有风格 → ✅ 直接使用（快速通道）
  │   标记验证计数 +1
  ├─ AI 推荐 - 知识库已有风格 → 🆕 新发现！
  │   ├─ 质量评估通过 → 采纳推荐，自动注册到缓存表（与已验证权重平等）
  │   └─ 质量不足 → 保留在备选列表，不进入主推荐
  ├─ AI 推荐包含已有风格的变体 → 🔄 变体发现
  │   标记为已有风格的 sub-type，记录触发场景
  └─ 输出：
      ├─ primary: 全局最优推荐 + 诚实标注
      ├─ alternatives: 2-3 个备选方向 + 诚实标注
      ├─ discoveries: 新发现（如有）
      └─ safety_excluded: 仅列出安全红线排除的（如有）
```

### 关键变化 v2.1：规则从"排除"变"标注"

```
v1.0：
  题材+光线+情绪组合不在表中 → 参照最接近行 → 标记"风格手动匹配"
  结果：用户看到一个"还行"的推荐，没有惊喜

v2.0：
  场景不在知识缓存中 → AI 主动搜索发现 →
  ├─ 找到了更好的匹配 → 给用户惊喜 + 入库
  └─ 确认知识库中的最佳匹配仍然是全局最佳 → 给用户解释为什么
  结果：用户要么得到惊喜，要么得到"这个确实最适合你"的确定性
  
  但问题：AI 搜索前被规则预过滤——搜不到"逆光通透"因为光线是顺光就排除了

v2.1：
  场景不在知识缓存中 → AI 在开放世界自由搜索（无预过滤）→
  ├─ 找到了最佳匹配（可能是逆光通透，虽然当前是顺光）→ 
  │   ├─ 标注"🟡 当前顺光——可利用地面反射模拟逆光，效果约 70%"
  │   └─ 用户看到全局最优 + 诚实评估
  ├─ 确认缓存中的最佳匹配仍然是全局最佳 → 给用户解释为什么
  └─ 安全红线（危险机位）→ 唯一硬排除
  结果：用户始终看到这个场景的全局最优解
```

### 3.3 缓存命中 vs AI 发现 v2.1

```
缓存命中（该组合在上表中存在，验证≥2）：
  → 作为候选之一参与 AI 综合判断
  → AI 仍会搜索确认是否还有更好的（v2.1：不受预过滤限制）
  → 如果 AI 确认缓存仍然最优 → 直接使用，不做无效搜索
  → 如果 AI 发现更好的 → 新发现与缓存权重平等——诚实标注两者的可执行性差异

缓存缺失（该组合不在上表中）：
  → 不意味着"没有匹配"——意味着"还没探索过"
  → AI 全力搜索发现（v2.1：在开放世界搜索，无预过滤）
  → 找到后自动注册到缓存表
  → 下一个人来秒出

缓存存在但验证=1（新注册）：
  → 与已验证≥3的条目权重平等参与
  → AI 会特别关注搜索结果是否支持或挑战这个新条目
  → 如果搜索结果一致 → 验证+1，置信度提升
  → 如果搜索结果不一致 → 标记 contested，积累更多验证
```

## 四、AI 搜索发现指南

### 4.1 搜索触发条件

以下任一情况，AI 执行搜索发现：

| 条件 | 触发 | 搜索深度 |
|------|:--:|------|
| 场景组合不在缓存表中 | ✅ | 深度搜索（5-7 次 WebSearch） |
| 缓存命中但验证 < 2 | ✅ | 中度搜索（3-4 次 WebSearch，验证为准） |
| 缓存命中且验证 ≥ 3 | 🚫 跳过搜索 | 直接使用缓存（除非用户要求探索） |
| 用户选择"✨ 脑洞大开" | ✅ | 广度搜索（不限于可执行性，搜创意） |
| 用户切换题材 | ✅ | 中度搜索（新题材的匹配关系） |

### 4.2 搜索策略

```
搜索模板（按顺序，可并行）：

#1: "{场景一句话描述} {光线特征} photography style inspiration"
    → 目标：全球范围内的风格参考

#2: "{题材} {光线条件} {情绪氛围} 摄影 风格 怎么拍"
    → 目标：中文社区的实际拍摄经验

#3: "{类似场景} photographer portfolio reference"
    → 目标：找到拍过类似场景的摄影师

#4: "{场景关键词} {风格候选1} {风格候选2} which style works best"
    → 目标：风格对比和选择依据

#5 (如适用): "{场景} {设备类型} photography technique"
    → 目标：设备特定的技法参考
```

## 五、自动知识沉淀 🆕

### 5.1 发现驱动的采集

v1.0：知识空白 → 兜底 → 用户无感 → 永远不补
v2.0：知识空白 → AI 搜索 → 找到答案 → 自动入库 → 下次秒出

```
每次方案生成都是一次知识发现机会：

方案生成完毕 →
  ├─ 检查方案中使用的风格匹配关系
  │   ├─ 在 style-router 缓存表中？ → 验证计数 +1
  │   └─ 不在缓存表中？ → 🆕 自动注册
  │
  ├─ 检查方案中产生的风格变体
  │   ├─ 如"清冷森系"是从"森系"变体而来
  │   ├─ 变体参数已在方案中明确（色温-15/绿色往青调等）
  │   └─ → 🆕 自动注册为风格变体
  │
  ├─ 检查方案中引用的大师视角
  │   ├─ 如"川内伦子 × 河边人像"这个组合
  │   └─ → 🆕 注册到 master-router 的场景匹配
  │
  └─ 输出变更摘要（静默，不打断用户体验）
```

### 5.2 轻量采集 vs 完整采集

| | 轻量采集（自动） | 完整采集（手动 /zhichu-collect） |
|---|---|---|
| 触发 | 方案生成时自动 | 用户主动调用 |
| 搜索 | 利用方案生成时的搜索结果 | 全新 Phase 1 多源搜索 |
| 参数提取 | AI 从方案中提取 | 完整 Phase 2 结构化分析 |
| 注册 | 写入缓存表 + 标记 `discovered` | 完整 Phase 4 全文件注册 |
| 置信度 | medium（需后续验证） | high（经过完整流程） |
| 用户感知 | 无感知（后台自动） | 有感知（输出变更摘要） |

### 5.3 自动注册到缓存表的格式

轻量采集写入 style-router 缓存表：

```markdown
| {题材} | {光线} | {情绪} | → {主风格} | → {变体风格} | → {破格方案} | 1 🆕 |
```

同时在风格源文件中追加一条 `discovered_from` 记录：

```markdown
<!-- discovered: 2026-07-23 | scene: "百善镇河畔+人像+户外软光+温暖松弛" | confidence: medium -->
```

## 六、风格冲突处理 v2.1

| 冲突 | 处理 | 优先级 |
|------|------|:--:|
| 危险机位 | **硬排除**——安全是唯一红线 | 最高 |
| 光线物理不完全匹配 | **诚实标注**——🟢完美/🟡可模拟(标注效果%)/🔴需等待 | 标注优先 |
| 设备不完全匹配 | **诚实标注**——🟢直接拍/🟡微调/🟠替代方案(标注效果%) | 标注优先 |
| AI 推荐与缓存不一致 | **AI 优先**——缓存是历史，AI 搜索是现在。但标记差异供后续验证 | AI > 缓存 |
| AI 推荐存在争议（搜索结果不一） | 标记 `contested`，同时呈现多个方向让用户选 | — |
| 审美冲突（如暖情绪+冷色调推荐） | **不排除**——冷色调+暖情绪可以是复合情绪的高级表达 | 最低 |
