# 匹配路由层 · 总纲 v2.0

## 一句话定义

**匹配路由层 = AI 引擎主导 + 规则护栏约束 + 知识缓存加速。** AI 不是兜底——AI 是引擎。规则不是驱动——规则是护栏。知识库不是真理——知识库是缓存。

---

## 一、v1.0 → v2.0 的核心变化

### v1.0 的架构问题

```
豆包视觉识别 → "室内漫射软光、暖色调"
                    │
         ┌──────────┴──────────┐
         │  7 个路由器并行查表    │
         │  各自输出独立结论      │
         │  没有人说"这个场景     │
         │  最动人的是什么"      │
         └──────────┬──────────┘
                    │
         审美主张引擎 → 分类标签
                    │
         方向选择器 → 简单拍/最出片
                    │
         兜底 → "匹配不到→最接近的行"
         
问题：
1. AI 是兜底，不是引擎——规则跑完了才轮到 AI
2. 兜底逻辑让用户无感——"还行"但没惊喜
3. 知识空白永远不补——兜底替代了发现
4. 审美主张是分类学，不是洞察
```

### v2.0 的新架构

```
┌─────────────────────────────────────────────────────────────┐
│                    🧠 AI 引擎层（主导）                        │
│                                                              │
│  场景输入 → AI 沉浸理解场景                                   │
│          → AI 搜索全球最佳风格匹配                             │
│          → AI 洞察最动人的那个瞬间                             │
│          → AI 从洞察生长创作方向                               │
│          → AI 发现知识空白并自动填补                           │
│                                                              │
│                    ↓ 约束传入                                 │
│                                                              │
│  🛡️ 规则护栏层（约束，不驱动）                                 │
│  ├─ 光线物理约束：硬排除（顺光拍不了逆光通透）                   │
│  ├─ 设备硬约束：硬排除（没长焦拍不了空间压缩）                   │
│  └─ 安全边界：不推荐危险机位（唯一不变量）                      │
│                                                              │
│                    ↓ 结果沉淀                                 │
│                                                              │
│  📚 知识缓存层（加速，不限制）                                  │
│  ├─ 已验证匹配 → 快速通道（验证 N 次）                         │
│  ├─ 新发现匹配 → 自动注册（标记 discovered）                   │
│  └─ 每次使用都是知识发现机会                                   │
└─────────────────────────────────────────────────────────────┘
```

## 二、匹配工作流 v2.0

```
阶段 1A：豆包视觉识别 → 场景完整描述
        │
        ▼
阶段 1B：规则护栏（硬过滤）
        ├─ light-router   → 光线 → 排除物理不可行的风格
        └─ user-capability → 设备 → 排除设备做不到的方案
        │
        ▼
阶段 1C：AI 引擎（主导匹配）🆕
        ├─ style-router v2.0  → AI 搜索发现最佳风格 + 知识库对比
        ├─ color-router       → 色彩策略 + 情绪映射
        ├─ space-router       → 构图候选 + 景别偏好
        ├─ texture-router     → 质感策略 + 风格兼容
        ├─ mood-router        → 情绪→视觉参数翻译
        ├─ genre-router       → 题材→审美优先级权重
        └─ master-router      → 大师匹配
        │
        ▼
阶段 1C.5：审美主张引擎 v2.0 🆕
        输入：AI 搜索结果 + 所有路由器输出 + 设备约束
        输出：场景洞察（不是分类标签）
              → 创作方向生长（放大/呼吸/转移/反转/致敬）
              → 设备翻译（用优势重新定义方向）
              → 排除决策（不应该，不是做不到）
        │
        ▼
阶段 1D-2：方向选择器 v2.0 🆕
        ├─ 🟢 现在就拍：零门槛，30 秒出片
        ├─ 🔥 最出片：社交验证，高辨识度
        └─ ✨ 脑洞大开：不限条件，摄影的可能性
        │
        ▼
阶段 3：方案生成（从洞察和创作方向展开）
        │
        ▼
阶段 3.5：自动知识沉淀 🆕
        检查匹配关系是否在缓存中
        → 不在 → 自动注册
        → 在 → 验证计数 +1
```

## 四、冲突解决优先级 v2.0

```
物理硬约束（光线+设备）         ← 最高优先级，一票否决
    ↓
AI 搜索发现                     ← 主导匹配，不是兜底
    ↓
知识缓存验证                    ← 加速优先（已验证 N 次 > 新发现）
    ↓
审美洞察                       ← 决定"应该拍什么"
    ↓
色彩/质感/情绪兼容性            ← 软约束，可被审美洞察覆盖
```

具体规则：
1. **光线物理不可行** → 硬排除。不需要 AI 判断。
2. **设备硬约束** → 硬排除。不需要 AI 判断。
3. **AI 推荐与缓存不一致** → AI 优先。缓存是历史，AI 搜索是现在。标记差异供后续验证。
4. **审美冲突** → 不硬排除。冷色调+暖情绪可以是复合高级表达。

## 五、核心设计原则 v2.0

1. **AI 是引擎，不是兜底**：规则跑了 AI 才上场 → 错误。AI 主导搜索和匹配，规则只做硬过滤。
2. **兜底不存在**：匹配不到 → AI 搜索发现 → 找到答案 → 入库。不是"降级到最接近的行"。
3. **每次使用都是知识发现**：方案生成 → 检查匹配关系 → 不在缓存 → 自动注册。知识库是活的。
4. **洞察优于分类**：不回答"这个场景属于哪一类"——回答"这个场景最动人的那个瞬间是什么"。
5. **惊喜感是功能，不是 bonus**：脑洞大开不是附加功能——是保证用户记住这个 app 的核心机制。
