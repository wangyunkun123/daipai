# 创作技法路由 v1.0

## 核心设计哲学

```
风格路由回答：这个场景用什么风格拍最好看？
技法路由回答：在这个风格下，站到哪里、怎么取景——照片立刻不一样？

风格告诉你"调什么色"。
技法告诉你"换个角度看世界"。

前者是方向和审美的选择。
后者是在选定方向上丰富执行细节。

两者的关系不是并行——是先后：
  先找到风格（风格路由）→ 再在风格下找技法（技法路由）
  找不到风格？→ 诚实面对——从技法出发，帮用户发现这个场景的惊喜
```

**技法路由不是又一个匹配表。它不回答"这个场景应该匹配哪些技法"——那是"为了加技法而加技法"。技法路由是 AI 搜索的副产物：AI 在开放世界搜索拍摄技巧 → 从搜索结果中获得启发 → 自然融入创作方向。**

```
风格路由的路径：AI 搜风格 → 缓存命中 → 诚实标注 → 审美主张
技法路由的路径：AI 搜技法 → 获得启发 → 自然融入方案 → 缓存积累

两条路径并行，在审美主张引擎汇合。
风格给了方案的"色调和质感"。
技法给了方案的"视角和动作"。
```

### 为什么第一次大海游艇让人眼前一亮

```
第一次大海游艇（无模板、无约束）：
  AI 被问了一个问题："这个场景，怎么拍会更好看？"
  → 高角度俯拍——把游艇和人物压缩在一层平面上
  → 变换姿势——让她不看镜头，望向海面
  → 换景别特写——只拍她手指划过栏杆的瞬间
  → 前景画框——用船舷线条框住人物
  
  这些建议的共同点：都是按下快门前的事。
  用户不需要调色、不需要后期、不需要等光线。
  用户只需要——站到不同的位置、选不同的景别、引导不同的姿势。

后来的模板驱动：
  AI 被要求填空："方案名称 + 要准备什么 + 就这么拍 + 💡"
  → 填完收工。模板让 AI 变成了填空题机器。
  → 同一个场景的不同方案只是"构图维度的排列组合"——
    三分法→前景虚化→留白→引导线。像在做选择题，不像在创作。
```

**技法路由的使命：把 AI 从"填空题机器"变回"发现者"。**

## 一、技法的定义边界

### 什么是技法（进入技法路由的范畴）

| 范畴 | 定义 | 示例 |
|------|------|------|
| **视角变化** | 改变拍摄位置/高度/方向来改变画面 | 蹲到沙地高度、高举俯拍、侧面切入 |
| **景别取舍** | 改变取景范围来改变视觉重心 | 只拍手和道具不拍脸、退到人只占画面 10% |
| **前景利用** | 在镜头前放置元素制造层次 | 树干做画框、沙地纹理当前景、玻璃反光叠影 |
| **光影发现** | 利用现有光线的非常规方式 | 只拍光斑不拍全身、用地面反光做第二光源 |
| **元素排除** | 通过角度/景别规避干扰 | 蹲下来让杂乱背景被草地遮挡 |
| **姿势引导** | 引导被摄者改变身体线条和情绪 | "别看镜头，看那边""手放松，像刚放下东西" |
| **对比制造** | 利用场景中的大小/色彩/新旧对比 | 人物渺小 vs 自然宏大、红衣 vs 绿背景 |
| **非常规机位** | 打破"站着拍"的习惯 | 贴地、高举、侧入、通过缝隙拍 |

### 什么不是技法（不进入技法路由）

| 非技法范畴 | 原因 | 归属 |
|-----------|------|------|
| 后期调色方案 | 是后期，不是前期 | → 风格路由的色彩策略 |
| 设备参数设置 | 是操作，不是创作 | → 设备翻译层 |
| 滤镜/预设推荐 | 是后期选择 | → 生图提示词 / 后期工具建议 |
| 布光方案 | 需要额外设备 | → 仅 🔴 高成本动作标记，不进入技法缓存 |
| 特殊镜头选择 | 设备依赖 | → 设备翻译层的替代方案 |
| 后期合成/多重曝光 | 是后期技术 | → 仅在"✨ 脑洞大开"中作为参考 |

**一句话：技法是用户在按下快门前能做的事。不依赖后期软件、不依赖额外设备（或仅需日常物品）、不改变场景本身的物理条件。**

### 例外：以技法为特征的艺术风格

某些风格的辨识度恰恰来自特定技法——这些技法不属于"为了加技法而加技法"，而是风格的构成要件：

| 风格 | 核心技法 | 处理方式 |
|------|---------|---------|
| Lofi 直闪 | 强制闪光灯 | 属于风格定义的一部分——必须包含 |
| 纪实粗粝 | 高反差+抓拍 | 属于风格定义的一部分 |
| 微观微距 | 极近距离拍摄 | 属于风格定义的一部分 |
| 梦幻柔美 | 柔光滤镜/前景虚化 | 属于风格定义的一部分 |
| 光绘/慢门 | 长曝光+光源移动 | 仅在"脑洞大开"中出现 |

> **规则**：如果某个技法在风格配方文件（`style-recipes/`）中被列为该风格的核心技法，则它属于风格路由的范畴，不通过技法路由重复匹配。

## 二、搜索策略 v1.1

> **v1.1 核心变更：技法搜索从"与风格搜索并行"改为"风格确定后触发"。风格无效时启动备用路线（技法出发）。**

### 2.1 搜索触发（双模式）

```
阶段 1C AI 引擎：

  Step A: 风格搜索 → 输出结果

    ├─ 匹配到合适风格（≥B级命中）→ 进入 主线模式
    │
    └─ 无合适风格（C级+全部🔴诚实）→ 进入 备用模式


主线模式（风格→技法）：
  风格已确定 → 在此风格下搜索技法 → 技法丰富方案执行细节

备用模式（技法→惊喜）：
  风格不确定 → 从技法出发 → 搜创意拍法 → 技法驱动方案
  （方案不标注风格名，只给拍法建议）
```

### 2.2 主线模式搜索模板（风格确定后，1-3 路）

```
技法搜索在风格确定后执行——搜索词中融入风格名：

#T1: "{风格名} {场景} 拍摄技巧 手机摄影 构图"
    → 目标：此风格在此类场景中的具体执行技巧
    → 提取：具体操作步骤 + 场景适配

#T2: "{style} {scene} in-camera technique composition posing angle"
    → 目标：英文社区在此风格下的创意技法
    → 提取：机位/角度/景别/姿势引导

#T3: "{风格名} {弱项维度} 拍摄技巧"  ← 针对性补强
    → 目标：补强此风格在当前场景下的操作短板
    → 例："安静真实 构图变化 技巧"（安静真实容易构图单调）
    → 提取：打破此风格常规套路的新角度
```

### 2.3 备用模式搜索模板（无风格时，2-3 路）

```
风格搜索未找到合适方向 → 不编造风格 → 从技法出发：

#T1: "{场景描述} 创意拍摄 角度 构图 惊喜 手机摄影"
    → 目标：中文社区中此场景的惊喜拍法
    → 提取：不依赖风格标签的纯技法创意

#T2: "{scene} unexpected angle composition technique unique perspective"
    → 目标：英文社区中打破常规的拍摄角度
    → 提取：机位/视角/非常规取景

#T3: "{场景标志性元素} 拍摄技巧 局部 特写 创意"
    → 目标：从场景中某个具体元素出发的拍法
    → 提取：元素特写 + 非常规视角
```

### 2.4 搜索深度调节

| 风格命中 | 技法缓存命中 | 技法搜索深度 | WebSearch |
|:--:|:--:|------|:--:|
| S/A | S/A | 轻量确认 | 0-1 次（缓存已有丰富技法，确认不重复即跳过）|
| S/A | B/C | 主线模式 | 1-3 次 |
| B | S/A | 主线轻量 | 0-1 次 |
| B | B/C | 主线模式 | 1-3 次 |
| C（诚实）| — | 备用模式 | 2-3 次 |

### 2.5 来源权重与诚实机制 v1.1

**来源权重**（与风格路由 §4.2 统一）：

```
🏋️ 高权重（可在方案中引用来源）：
  - 专业摄影教程/杂志
  - 摄影师个人作品集
  - 社交平台高粉博主（≥10万粉）分享的拍摄教程
  - 高赞高收藏帖子（≥5000赞或收藏）

⚖️ 中权重（作灵感方向，谨慎引用）：
  - 普通社交帖子（<5000赞）
  - YouTube 摄影教程

📎 低权重（仅灵感，不引用来源）：
  - 内容农场 / 疑似AI生成
  - 泛泛的"N个技巧"列表
```

**诚实机制**：

```
技法搜索质量自检：

每路搜索标注：
  🟢 = 返回具体、可操作、场景相关的技巧
  🟡 = 有相关信息但不够具体
  🔴 = 无结果/完全无关

综合判断：
  ≥1路🟢 → 正常流程，技法结果融入方案
  全部🟡 → 仅使用缓存中的技法（如有），不强行注入搜索到的模糊信息
  全部🔴 → 诚实不编：
    - 主线模式：方案只基于风格定义和摄影原理，不编造"搜索发现的技巧"
    - 备用模式：诚实告知「没搜到这个场景的公开参考。下面的建议来自摄影原理。」
```

### 2.6 展示原则

风格和技法在最终方案中**不分家**。用户看到的是一份完整的口语化拍摄方案——不需要知道哪个来自风格搜索、哪个来自技法搜索。技法融化在方案的「就这么拍」和「要准备什么」中。唯一需要区分风格/技法来源的是 AI 自己在生成前的内部推理。

## 三、技法缓存表

### 3.1 缓存的定位

技法缓存与风格缓存遵循同一原则：**不是真理——是经过验证的历史最佳实践。AI 搜索是引擎，缓存是加速器。**

```
风格缓存的作用：加速匹配——已验证的场景→风格映射直接复用
技法缓存的作用：加速启发——已验证的场景→技法发现直接作为灵感候选

两种缓存都是"用得越多→越密→越准→越快"的正循环。
```

### 3.2 source_type 来源类型 🆕 v1.3

每条技法必须标注来源类型：

| source_type | 含义 | 方案中的引用方式 |
|------------|------|----------------|
| `community` | 从小红书/Instagram/微博等社区提取的真实分享 | 可引用来源+作者："小红书上有人分享过——" |
| `tutorial` | 从专业摄影教程/杂志/YouTube 提取 | 可引用出版物/频道名 |
| `portfolio` | 从摄影师个人作品集/画廊提取 | 可引用摄影师名 |
| `inference` | AI 基于摄影原理推理（以上三类均为空） | 诚实标注："这是 AI 想到的方法，还没人试过——说不定有惊喜" |

#### inference 条目管理规则 v1.3 🆕

```
inference 条目的定位：
  AI 基于摄影原理推导的原创技法——逻辑合理但未经社区验证。

推荐约束：
  ├─ 仅在缓存命中 ≥ B 级时进入推荐候选
  ├─ 不作为 🟢 现在就拍 的主推荐方向（主推荐仅用 community/tutorial/portfolio）
  ├─ 可在 🔥 最出片 或 ✨ 脑洞大开 中作为备选出现
  └─ 展示时必须携带 inference 诚实话术

晋升机制（inference → community/tutorial/portfolio）：
  每次使用此技法时，在 WebSearch 中顺带搜索验证：
    "{技法关键词} 摄影 教程 小红书"
  
  搜索到 ≥ 3 篇真实社区分享 → 升级 source_type + 更新来源字段
  搜索到 1-2 篇 → 保持 inference，在来源中追加 "已有少量验证: {链接}"
  搜索到 0 篇 → 保持 inference，不做变更
  
  晋升检查周期：每次缓存命中时顺带检查（零额外搜索成本）
  
降级/淘汰：
  连续 5 次推荐但用户未采纳 → 标记 low_confidence
  连续 10 次未采纳 → 移出主缓存表，归档到 inference_archive
```

### 3.4 技法缓存命中分级

与风格缓存同样的 S/A/B/C 四级体系，但判定维度不同：

#### 3.4.1 三维匹配规则

**场景类型匹配**（权重 40%——技法是场景依赖的）：

| 状态 | 判定 | 示例 |
|------|:--:|------|
| ✅ 完全一致 | 场景类型+关键元素都匹配 | 海滩+人物=海滩+人物 |
| ⚠️ 相近 | 场景类型相同，关键元素不同 | 海滩+人物 ≈ 海滩+建筑 |
| ❌ 不同 | 场景类型不同 | 海滩+人物 ≠ 室内+静物 |

**光线条件匹配**（权重 35%——决定技法是否可执行）：

| 状态 | 判定 | 示例 |
|------|:--:|------|
| ✅ 一致 | 光质+方向接近 | 户外软光=户外软光 |
| ⚠️ 可类比 | 光质接近，方向不影响技法 | 窗边侧光 → 户外侧光（技法逻辑相同）|
| ❌ 相反 | 光质相反 | 硬光剪影技法 ≠ 软光场景 |

**设备能力匹配**（权重 25%——技法对设备有要求）：

| 状态 | 判定 | 示例 |
|------|:--:|------|
| ✅ 直接可用 | 设备天然执行此技法 | 手机超广角 → 低角度前景拉伸 |
| ⚠️ 需调整 | 可通过简单调整执行 | 无长焦 → 2× 裁切+靠近替代 |
| ❌ 不可用 | 设备无法执行 | 无超广角 → 无法做前景拉伸效果 |

#### 3.4.2 四级命中

| 等级 | 条件 | 搜索深度 | 动作 |
|:--:|------|:--:|------|
| **S** | 三维全中 + 验证 ≥ 3 | 零搜索 | 秒出——缓存中的技法直接作为灵感候选 |
| **A** | 三维全中 + 验证 1-2 | 确认搜索 1-2 次 | 缓存技法进入候选，轻量确认新技巧 |
| **B** | 二维命中 + 一维相近 | 中度搜索 2-3 次 | 缓存技法作参考，补充搜索同类场景 |
| **C** | 二维以下命中 | 深度搜索 3-4 次 | 缓存无有效参考，开放世界发现 |

#### 3.4.3 判定流程

```
当前场景 → 提取三维特征（场景类型/光线/设备能力）
    │
    ▼
扫描技法缓存每一行 → 计算匹配度：
    ├─ 场景类型：完全一致=2分，相近=1分，不同=0分
    ├─ 光线条件：一致=1.5分，可类比=1分，相反=0分
    └─ 设备能力：直接可用=1.5分，需调整=0.5分，不可用=0分
    │
    ▼
取最高分的那行：
    总分 ≥ 4.0 → S/A 级（取决于验证次数）
    总分 2.5-3.9 → B 级
    总分 < 2.5 → C 级
```

## 四、技法融入方案的方式

### 4.1 核心原则：技法不是方案的"附加标签"

```
❌ 错误方式：
  方案生成完毕 → 检查"这套方案用了几个技法？"→ 不够就加
  结果：方案像是被强行贴了技法贴纸——用户感受不到有机的联系

✅ 正确方式：
  AI 在搜索阶段看到技法 → 被某条技法启发 →
  "这个场景如果用低角度拍，前景的沙地纹理会变成抽象画"→
  方案从这个启发中生长出来 → 技法已经融化在方案里了
```

### 4.2 融入的两种方式

**A. 技法启发了一整方案（主驱动）**

```
AI 搜到"蹲到沙地高度拍海滩人像"
  → 被启发："这个场景的沙地上有光斑——低角度会把光斑变成前景纹理"
  → 生长出一套方案："蹲下来——让沙地变成你的第一层画布"
  → 方案里的「就这么拍」已经包含了技法的操作
  → 🎯 换个思路 解释为什么这个视角和平时不一样
```

**B. 技法为已有方案提供了新角度（增强）**

```
已有方案 1："就这样，别叫她"（平视中景，记录松弛状态）
AI 搜到"只拍光斑落在衣服上的局部"
  → 被启发："同一个场景，可以不拍整体——只拍光在她身上做了什么"
  → 增加方案 4："不拍海滩——只拍她球衣上的光斑"
  → 方案 1 和方案 4 的差异是"看见的方式"完全不同
```

### 4.3 不用的技法也要说出来

如果 AI 搜索到了很棒的技法，但经过审美判断后认为不适用于这个场景——诚实告知：

```
💡 还有一种拍法——利用水面倒影拍出对称构图。
但是这个场景的浅溪水流较快，水面不平静，倒影会很破碎。
如果以后遇到平静的水面（湖/池塘/雨后的水洼），可以试试。
```

> 这不浪费——它在教育用户。用户下次遇到平静水面时会想起这句话。

## 五、输出增强：🎯 换个思路

### 5.1 定位

**「🎯 换个思路」不是技法说明——是用一句话告诉用户：这个方案在"看见的方式"上和其他方案有什么不同。**

| 字段 | 回答的问题 | 长度 | 必填 |
|------|-----------|:--:|:--:|
| 💡 为什么好看 | 这个方案的光线/构图/空间原理 | 1-2 句 | ✅ 必填 |
| 🎯 换个思路 | 这个方案的"观看角度"和其他方案的本质不同 | 1 句 | ⚪ 可选——当技法确实带来了不同视角时才出现 |

### 5.2 写法

```
好的「换个思路」：
  ✅ "蹲到和她一样高——你不是在'拍她'，你是在'成为她'。"
  ✅ "退到人只占画面 10%——人不重要，天和海才是主角。"
  ✅ "你不拍'她在海滩上'——你拍'光在她身上做了什么'。"
  ✅ "从小狗的视角看世界——20cm 高度看到的和 170cm 完全是两个世界。"

坏的「换个思路」（如果只是凑格式）：
  ❌ "使用了三分法构图"（这是技法名称，不是思路改变）
  ❌ "低角度拍摄有新鲜感"（空洞——到底新鲜在哪里？）
  ❌ "换个角度"（废话——方案 2 本来就和方案 1 角度不同）
```

### 5.3 何时出现

| 条件 | 是否出现 |
|------|:--:|
| 方案确实由某个技法启发而来——技法是方案的"种子" | ✅ 出现——解释观看角度的本质差异 |
| 方案的核心差异是景别/构图的常规变化（中景→近景）| ❌ 不出现——方案名本身就区分了，不需要硬凑 |
| 方案的"为什么好看"已经充分传达了思路变化 | ❌ 不出现——不重复 |

**一句话：有真正的"观看方式"变化才写。没有就不写。不凑数。**

## 七、自动知识沉淀

### 7.1 沉淀触发

与风格路由 §五同样的机制——方案生成完毕后静默检查：

```
检查 1: 方案中使用的技法是否在技法缓存表中？
  ├─ 在 → 验证计数 +1
  └─ 不在 → 🆕 自动注册到技法缓存表
            写入格式：| {场景类型} | {技法名} | {来源} | {source_type} | {操作描述} | {设备} | 1 🆕 |

检查 2: AI 搜索发现了新技法但未被任何方案采用？
  └─ → 🆕 自动注册到缓存表（标记 confidence: low——需后续验证）
        即使本次未使用，下次类似场景会自动出现在候选池中

检查 3: 方案中的技法是否已有风格归属？
  ├─ 如"蹲到宠物高度"→ 不属于任何特定风格 → 保留在技法缓存
  └─ 如"直闪"→ 属于 Lofi 直闪风格的核心技法 → 不重复注册到技法缓存
```

### 7.2 轻量采集格式

```
| {场景类型} | {技法名} | {来源} | {source_type} | {操作描述} | 🟢/🟡 | 1 🆕 |
```

## 八、质量自检

| # | 检查项 | 不通过处理 |
|---|--------|----------|
| 1 | 技法搜索是否在风格确定后触发（主线模式）或无风格时启用备用模式？ | 检查搜索触发逻辑 |
