# 带拍 · 方案呈现设计框架

> 2026-07-28 | 基于 7 种视觉引导方案的失败经验总结

---

## 一、核心发现：信息的"可标注性"是不均匀的

7 种方案（幽灵分身、小地图、三步序列、分镜对比、地面标记、结果导向、第一人称）的集体失败
不是因为"设计不够好"，而是因为**试图把不同性质的信息强行压进同一个二维平面**。

一张静态照片能承载的标注信息和不能承载的标注信息之间存在一条清晰的边界：

### 可在照片上标注的（框内信息）

这些信息描述的是**最终构图里应该出现什么**，与摄影师站位无关：

| 信息类型 | 标注方式 | 清晰度 |
|---------|---------|:---:|
| 构图网格 | 九宫格线，透明度 15% | ★★★★★ |
| 主体位置 | 金色定位圈 + 标签 | ★★★★★ |
| 裁切参考 | 半透明遮罩标记裁掉区域 | ★★★★ |
| 光线方向/质感 | 半透明径向渐变叠加 | ★★★ |
| 景深分区 | 前/中/远景色区标记 | ★★★ |
| 引导线 | 沿画面内已有线条做高亮 | ★★★★ |
| 留白区域 | 半透明区域标记 | ★★★ |
| 水平线 | 水平参考线 | ★★★★★ |

### 不可在照片上标注的（摄影师动作 + 被摄者动态 + 抽象参数）

这些信息描述的是**从当前状态到目标状态的变化**，当前照片本身不包含目标视角的信息：

| 信息类型 | 为什么不能在原图上标注 | 应该放哪里 |
|---------|----------------------|-----------|
| 摄影师站位（前/后/左/右几步） | 原图是"当前位置"的视角，标注"去那边"是画饼 | 文字卡片 |
| 机位高度（蹲下/站立/高举） | 高度变化改变整个透视关系 | 图标+文字 |
| 拍摄角度（平视/俯拍/仰拍/侧面） | 侧面/俯拍的画面和当前完全不同 | 图标+文字 |
| 焦段选择 | 抽象参数，不可视化 | 图标+文字 |
| 被摄者姿势/动态 | 静态图不能表达"往前走然后回头" | 姿势参考图或文字 |
| 对焦/曝光操作 | 操作指令 | 文字 |
| **决定**：照片上只标注框内信息。摄影师动作、姿势动态、技术参数一律放文字卡片。 |

## 二、信息分类：五层模型

每一个拍摄方案需要传递的信息，归入五个层级：

```
Layer 1 ┃ 框内可见（构图/主体/光线/裁切）  → 标注在照片上
Layer 2 ┃ 拍摄者动作（站哪/蹲下/靠近/侧面） → 图标 + 一行文字
Layer 3 ┃ 被摄者动态（姿势/表情/互动）      → 参考图 或 一行文字
Layer 4 ┃ 技术参数（焦段/对焦/模式）         → 紧凑一行
Layer 5 ┃ 效果预期（成片感觉/AI特效预览）    → 文字 或 AI生成预览图
```

### 层级优先级原则

- **Layer 1** 是用户"看"到的 → 必须在照片上
- **Layer 2** 是用户"做"的 → 一行能说清就不两行
- **Layer 3-5** 按需展示，默认折叠不影响扫读

## 三、景别（Shot Size）自适应的标注策略

不同景别，可视环境量不同，标注和信息优先级也不同：

### 远景 / 大全景（环境为主，人物小）

```
照片标注：水平线 · 主体区域圈 · 引导线（如有）· 光线方向
文字优先：Layer 2（站位/焦段） > Layer 5（氛围） > Layer 3（人物动态不重要）
```

### 全景（人物全身 + 一定环境）

```
照片标注：九宫格 · 主体定位圈 · 光线方向 · 裁切（如有）
文字优先：Layer 2（站位/高度/角度） > Layer 3（姿势） > Layer 5（效果）
```

### 中景（半身，环境减少）

```
照片标注：九宫格 · 主体定位圈（精确到头部位置）· 光线质感
文字优先：Layer 2（微调距离/角度） > Layer 3（表情/眼神） > Layer 4（对焦/光圈）
```

### 近景 / 特写（面部或细节，几乎无环境）

```
照片标注：仅光线质感层（网格无用）
文字优先：Layer 3（表情/眼神方向） > Layer 4（对焦点） > Layer 2（基本不需要动）
```

## 四、摄像机角度（Angle）变化的处理

当方案要求变换角度时（如"从侧面拍"），当前照片的画面内容会**根本性改变**：

### 角度变化矩阵

| 角度变化 | 难度 | 处理方式 |
|---------|:---:|---------|
| 同角度，调整距离 | ★ | 文字"靠近/退后 N 步" |
| 同角度，调整高度 | ★★ | 高度图标 + 文字"蹲下/举高" |
| 小幅角度偏移（15-30°） | ★★★ | 方向图标 + 文字"往左移一步，身体右转" |
| 大幅角度变化（90°侧面） | ★★★★★ | 当前照片完全无法标注 → **需要 AI 生成目标视角预览** |
| 俯拍/仰拍 | ★★★★ | 高度图标 + 文字描述新的透视关系 |

### 角度变化的"诚实"原则

当前照片标注系统对角度变化有天然天花板。
如果方案的核心卖点就是"换个角度"，那应该：
1. 用 AI（Seedream）生成目标角度的预览图
2. 预览图 + 原图左右对比
3. 文字只写"走到侧面，让相机看到这样的画面"

## 五、人物动态（Subject Dynamics）的处理

这是最需要但最难标注的信息。四种可选方案：

| 方案 | 成本 | 清晰度 | 适用场景 |
|------|:---:|:---:|---------|
| **姿势图标库** | 低（预制） | ★★★ | 常见姿势（站/坐/蹲/靠/走/跑/回头） |
| **AI 姿势参考图** | 中（调用生图API） | ★★★★ | 特定姿势（"侧身45°回头看镜头"） |
| **火柴人简笔画** | 低 | ★★ | 快速示意，但可能显得不专业 |
| **纯文字** | 零 | ★★★ | 简单动作（"蹲下摸狗的头"） |

**建议**：Layer 3 默认用一行文字，高频姿势可用图标库。AI 姿势参考图作为未来的增值功能。

## 六、后期 AI 特效（Future AI Effects）

这是最值得投入的方向——它直接解决了"消费环境和执行环境的 gap"：

### 概念

不告诉用户"怎么拍"，直接给他们看"拍出来修完图是什么样"。

```
┌─────────────────────────────────┐
│  AI 生成：按方案拍 + 后期效果    │
│  (Seedream img2img + style)     │
│                                 │
│  这张图让用户一眼看到：          │
│  "我要的是这样的照片"           │
│                                 │
│  标注只在 AI 效果图上叠加：      │
│  · 构图网格                     │
│  · 主体位置圈                   │
│  · "你的取景框应该框住这个范围" │
└─────────────────────────────────┘
```

### 为什么这比标注原图好

- AI 效果图 = 目标状态，不包含"现在的位置"信息 → 没有矛盾
- 用户只需要把取景框对齐 → 不需要理解"怎么走过去"
- "对齐取景框"是一个身体能执行的操作，不是认知任务

### 成本考量

- 豆包 Seedream API 已有 img_gen_prompt 字段
- 每个方案生成一张预览图 → 1-9 张图/次
- 如成本过高，可只给 Top 3 方案生成

## 七、推荐方案：混合卡片 v1

### 卡片结构

```
┌──────────────────────────────────┐
│                                  │
│   ANNOTATED PHOTO                │
│   (仅 Layer 1 标注)              │
│                                  │
│   标注内容：                     │
│   ┌ 九宫格线（白，透明度15%）    │
│   ┌ 主体定位圈（金，实线）       │
│   ┌ 光线方向渐变（暖/冷半透明）  │
│   ┌ 裁切遮罩（如有需要）         │
│                                  │
│   底部状态栏：                   │
│   [📷 方案1/3] [方案名称]       │
│                                  │
├──────────────────────────────────┤
│  Layer 2 ┃ 📍 你怎么拍         │
│  一行，图标驱动，动词先行         │
│  ← 左移两步 · 🧎 蹲下 · 主摄24mm │
├──────────────────────────────────┤
│  Layer 5 ┃ ✨ 效果预期         │
│  一行，感性描述                   │
│  温暖逆光穿过发丝 · 宠物看镜头    │
├──────────────────────────────────┤
│  Layer 3 ┃ 🎯 构图关键   [展开▾] │
│  默认一行，可展开查看完整内容     │
│  人物放在画面左1/3处             │
│  狗放在右1/3，视线交汇           │
│  顶部乱枝裁掉                    │
└──────────────────────────────────┘
```

### 这个设计的几个关键决策

1. **照片=构图参考，文字=行动指令**——各司其职，互不侵扰
2. **照片标注极简**——只有网格+定位圈+光线，不写字，不画箭头
3. **"你怎么拍"是第一优先级**——用户在拍摄现场只想知道这一个答案
4. **"效果预期"给方向**——不是技术描述，是感性画面，帮助判断"我拍到了吗"
5. **"构图关键"默认收起**——给想看的人看，不增加扫读负担
6. **所有标注自适应景别**——特写不画网格，远景加引导线

### 与技术实现的对接

当前 `server.py` 的方案结构：
- `subject` = Layer 1 主体位置（可标注）
- `shooter` = Layer 2 拍摄者动作（文字卡片）
- `gear` = Layer 4 技术参数（文字卡片）
- `enhance` = 裁切/构图建议（部分可标注 + 部分文字）
- `result` = Layer 5 效果预期（文字卡片）
- `img_gen_prompt` = AI 效果预览（未来功能）

**PIL 标注生成只需覆盖 Layer 1**：网格线 + 主体定位圈 + 光线渐变 + 裁切遮罩。
这比之前尝试的所有方案都简单，而且不会出错。
