# 隐形式方案相机 —— 产品思考

## 背景

在「带拍」项目中，我们已经很好地解决了风格选定和拍照方案制定的问题。但方案内容如何传递给用户一直是个痛点：

- 文字说明引导 → 拍摄现场没时间读
- 生成参考图 → 需要切换 App 对比
- 语音引导 → 理解需要脑力，和环境音冲突
- AR 辅助叠加 → 视觉混乱，叠加信息太多

**核心矛盾：方案越详细越好，但现场越简单越好。**

---

## 核心哲学

传统摄影指导的逻辑链：

```
方案内容 → 用户理解 → 用户记忆 → 现场回忆 → 手动执行 → 拍出照片
```

每一步都在流失。到"现场回忆"那一步，方案已经丢了 80%。

隐形方案相机的逻辑链：

```
方案内容 → 相机被改造 → 用户凭直觉操作 → 直觉行为天然命中方案 → 拍出照片
```

**用户完全跳过了理解和记忆。** TA 只是在"正常拍照"，但相机的每一个反馈都在把 TA 往方案的方向引导。用户以为是自己在做决定，实际上每个"感觉对了"的瞬间都是方案在设计。

这不是"教用户摄影"，这是**"把摄影知识编译进相机的物理行为里"**。

---

## 六个维度

不叠加任何文字、图标、引导线。只改变相机**已有的元素**的行为。

---

### 维度 1：取景器 —— 光的重力场

**不是画线，是改变"哪里好看"。**

技术：AI 实时分析画面，计算当前构图与方案理想构图的偏差，生成一个**亮度梯度蒙版**。

| 方案要求 | 取景器效果 |
|---------|----------|
| 主体在右侧三分之一 | 右侧区域微微更亮/更暖，其余区域存在不引人注目的暗角 |
| 上方大量留白 | 上半部分画面清晰明亮，下半部分有极轻微的暗化 |
| 中心对称构图 | 画面中心有一个极其微弱的亮区，边缘渐变暗 |
| 对角线构图 | 对角线上有一条肉眼几乎看不出来但潜意识能感知的微亮带 |

**关键参数**：亮度差异控制在 3-5%。超过 5% 用户会察觉"画面被改了"，低于 3% 没有引导效果。3-5% 刚好在意识阈值以下。

用户体验："这个角度看起来...更顺眼？" —— 他不会知道为什么，但身体会自然地让手机停在那个位置。

**更进一步：视觉重心吸附。** 当取景框里的主体靠近方案推荐的"黄金位置"时，主体区域会有一个非常微弱的暖色调增强。用户的潜意识会追逐这个暖意，像植物向光。

---

### 维度 2：曝光 —— 方案自带测光表

不是锁定参数，是**改变"曝光补偿的零点"**。

不同方案对曝光的偏好天差地别：

| 方案类型 | 曝光偏差 | 用户感受 |
|---------|---------|---------|
| 明亮小清新 | +0.7 EV | "今天光线真好" |
| 暗调情绪片 | -1.0 EV | "感觉很有氛围" |
| 逆光剪影 | -2.0 EV（锁死） | "自动拍出来的剪影好干净" |
| 高调白背景 | +1.5 EV | "背景好干净" |

**关键设计**：曝光补偿滑块依然可以手动调整，但**零点被重新定义了**。用户滑到中间位置就是方案的推荐值。TA 不需要知道"过曝"是什么意思，TA 只需要把画面调到"看着舒服"——而"舒服"已经被方案重新定义了。

**更进一步：区域曝光偏好。** 方案要求"人脸略亮一点"，那相机测光时自动给人脸区域加权 30%。用户什么也没调，拍出来人就是亮的。TA 会觉得"今天这部手机拍人真好看"。

---

### 维度 3：焦段 —— 有磁性的变焦

变焦滑杆上出现**看不见的磁力点**。

方案推荐 2×（50mm 等效人像焦段），那滑杆在 2× 的位置有一个微妙的**物理感觉变化**：

- 滑过 2× 时，反馈振动有一个轻微的"卡入"手感
- 滑杆在这个位置的滑动速度自动减慢 20%，让用户更容易精确停在这里
- 屏幕上在 2× 处的数字/刻度有一个几乎不可见的亮度提升

用户不是"被逼迫"用 2×，而是"用 2× 的时候感觉特别顺手"。

**更进一步：限制但不是禁止。** 如果方案强烈不建议使用超广角（会破坏某种构图风格），那 0.5× 以下的焦段滑杆阻尼加大。用户可以硬滑过去，但会感觉"有点费劲"。大部分人不会。

---

### 维度 4：角度和机位 —— 手机变成水平仪

利用陀螺仪和加速度计，把手机变成一个**方案感知的三维空间引导器**。

| 方案要求 | 手机行为 |
|---------|---------|
| 低角度仰拍 | 当手机降低到离地 30-50cm + 仰角 >15° 时，画面微微变亮 |
| 纯俯拍（Flat Lay） | 当手机接近完美水平（俯角 89-91°），出现一个极其微弱的"对上了"的呼吸灯效果 |
| 平视拍摄 | 当俯仰角接近 0° 时，快门按钮边缘微微发光 |
| 荷兰角（倾斜构图） | 当手机倾斜到方案要求的 ±15° 时，画面出现一个微妙的色彩饱和增强 |

**关键细节**：不是显示水平仪图标（那又变成信息叠加了），而是**用画面本身的质感变化来反馈**。画面变亮一点、颜色暖一点、暗角消失——用户的身体会追逐这些正向反馈，自然地调整到"对"的位置。

---

### 维度 5：时机 —— 快门按钮有心跳

快门按钮不再是死物。

当 AI 检测到画面条件匹配方案时，按钮出现**生命周期**：

```
条件勉强匹配 → 按钮边缘微弱呼吸光（亮度 10%）
条件接近理想 → 呼吸光变亮、频率变慢（亮度 30%）
条件完美匹配 → 按钮短暂亮起（亮度 60%），持续 0.5 秒后恢复
```

匹配条件取决于方案：

| 方案时机要求 | 检测逻辑 |
|------------|---------|
| "捕捉人物自然表情" | 检测到微笑/大笑/惊讶表情时触发 |
| "逆光中的发丝光" | 检测到主体边缘有高光溢出时触发 |
| "路人经过的对比" | 检测到画面中有人物从边缘进入构图区时触发 |
| "风吹动衣角" | 检测到布料/头发的运动矢量突增时触发 |
| "安静的空镜" | 检测到画面中无人物、无明显运动时触发 |

**用户看到按钮亮起来，自然地按下——TA 以为是自己在"抓住时机"，但实际上是 AI 在"呈上时机"。**

---

### 维度 6：后期 —— 一键方案的"色泽"

拍完的照片在相册缩略图里就已经是方案风格了。

不是事后套滤镜——**按下快门的那一刻，方案的色彩映射就已经应用在预览上**。用户拍的时候看到的就是方案色调的画面，拍完不需要后期。

但更关键的在这：**因为用户在取景时看到的就是方案色调，TA 的构图和光线选择也已经被这个色调影响了。**

比如一个暗调方案，取景器里就是暗的。用户会觉得"白天拍出来像黄昏，好酷"，然后 TA 会不自觉地去找更暗的背景、更戏剧性的光线——因为这样在取景器里"看起来更好"。**方案不只改变了成片，也改变了用户的审美判断。**

## 完整案例：逆光人像剪影

```
📱 用户选择方案 "逆光剪影"
    └→ 相机打开

🔦 用户举起手机对准夕阳下的朋友

    【发生了什么用户不知道的事】
    - 曝光零点自动偏移到 -2.0 EV
    - 测光权重向高光区域倾斜
    - 变焦滑杆在 2× 处有磁力点
    - 画面中心偏下区域有 4% 的亮度增强
    - 手机仰角在 5-15° 时画面微暖
    - 快门按钮开始监测逆光条件

👁️ 用户看到的：
    "咦，今天相机的画面感觉好柔和。"
    这个人在画面里站的位置...感觉这里站着比较好看？
    我把手机低一点...嗯这样画面好像更干净了。
    
    → 快门按钮边缘开始发光（AI检测到人脸+逆光条件）

👆 用户按下快门
    成片：完美剪影，人物轮廓清晰，背景暖橙色过曝。
    缩略图已经是成片色调，不需要调整。

💭 用户心理：
    "今天这张拍得真不错，可能是我找到感觉了。"
```

TA 不知道、也不需要知道的是：曝光、构图、角度、时机——这四件事没有一个是 TA 自己决定的。TA 只是在"凭感觉移动手机"和"在按钮好看的时候按下"。

**但 TA 的感觉完全是对的，因为相机重新定义了"好看"。**

## 方案对比：为什么这比已知方案都好

| 方案类型 | 用户注意力占用 | 学习成本 | 现场可执行性 | 复用性 |
|---------|-------------|---------|------------|-------|
| 文字说明 | 高（阅读+理解+记忆） | 高 | 差 | 低 |
| 参考图片 | 中（切换App对比） | 中 | 中 | 低 |
| 语音引导 | 中（听力通道+理解） | 中 | 中 | 低 |
| AR叠加 | 高（视觉混乱） | 低 | 差 | 中 |
| **隐形方案相机** | **零** | **零** | **极佳** | **高** |

**本质差异**：前四种都是"把信息传递给用户，让用户执行"。隐形方案相机是"把信息编译进交互，让相机执行，用户只负责感受"。

## 技术可行性

### 1. 实时构图评分
- CoreML + Vision 框架可以对人脸/身体做实时检测
- 对于非人物构图（风景、静物），可以使用轻量级显著性检测模型
- 每帧推理时间需 < 10ms（16ms 一帧，留 6ms 给其他处理）
- iPhone 12 及以上机型的 Neural Engine 完全有能力做到

### 2. 亮度梯度蒙版的实时渲染
- Metal Shader 可以在 GPU 上每帧生成，开销极低
- 梯度形状根据方案配置动态调整
- 性能影响 < 1% GPU 占用

### 3. 时机检测的条件组合
- 人物检测、表情识别、光流分析已经非常成熟
- 但组合条件的实时推理需要精细调优
- 初期可以只做"曝光条件匹配"和"人脸朝向检测"两个触发条件

### 4. 陀螺仪精度
- iPhone 的陀螺仪精度足够检测 1° 的角度变化
- 但长期漂移需要融合加速度计数据做补偿
- 相对角度检测（从初始位置开始的偏移）比绝对角度检测更可靠

## MVP 建议

挑三个最便宜、最显效的维度先落地：

```
┌────────────────────────────────────────┐
│  MVP: 三维隐形                          │
│                                        │
│  1. 曝光零点偏移                        │
│     → 方案选择后，曝光补偿默认值跟随方案  │
│     → 实现：一个参数的赋值               │
│     → 用户感知：★★★★★ "颜色好看很多"     │
│                                        │
│  2. 取景器亮度梯度                       │
│     → 方案指定的构图区域 4% 亮度增强      │
│     → 实现：Metal Shader 一个蒙版叠加     │
│     → 用户感知：★★★★ "这个角度好看"      │
│                                        │
│  3. 变焦磁力吸附                         │
│     → 方案推荐焦段有轻微触觉反馈          │
│     → 实现：UISlider + Haptic 回调       │
│     → 用户感知：★★★ "这个焦段顺手"       │
│                                        │
│  不做的（等验证后再加）：                  │
│  - 实时构图AI评分                        │
│  - 快门时机检测                          │
│  - 角度姿态引导                          │
│  - 即时风格预览                          │
└────────────────────────────────────────┘
```

三个改动加起来开发量不大，但用户拿到的相机体验已经有质的区别。

## 终极形态的想象

当六个维度全部实现后，用户体验变成这样：

- 选一个方案 → 打开相机
- 相机看起来和普通相机一模一样
- 没有任何提示、文字、图示
- 但用户每移动一下手机，画面都在用亮度、色调、振动说话
- 用户完全不需要思考，身体知道怎么动
- 快门在恰到好处的时候"提醒"用户按下
- 拍出来的照片不需要任何后期
- 用户觉得："我今天的摄影状态特别好"

**这就是隐形的意义：让方案消失，让好照片出现。**
