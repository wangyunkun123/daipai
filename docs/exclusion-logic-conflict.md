# 三文件"排除"逻辑冲突分析

**日期**: 2026-07-24 | **文件**: style-router.md vs direction-selector.md vs aesthetic-assertion.md

---

## 一、冲突还原

### 用一个具体例子走一遍 pipeline

**场景**：河畔人像，当前光线 = 顺光

### Step 1: style-router.md (阶段 1C) — "全量发现"

style-router 在开放世界搜索，发现了"逆光通透 × 河畔人像"。当前是顺光，但根据 v2.1 原则：

```
光线物理不完全匹配 → 诚实标注（不排除）
→ 标注为 🟡"当前顺光——可利用浅色河滩地面反射模拟逆光，效果约70%"
→ 进入 annotated_not_ranked 池（不是主推荐，但仍在候选池中）
```

**结论**：逆光通透**没有被排除**，带着 🟡 标注进入了候选池。

### Step 2: aesthetic-assertion.md (阶段 1C.5) — "审美筛选"

aesthetic-assertion 从洞察出发做排除：

```
排除不是因为"做不到"——是因为"不应该"。
```

- 逆光通透与洞察"安静的信赖"**不存在审美冲突**
- aesthetic-assertion 不会排除它
- 如果它通过了审美筛选，它继续留在候选池中

**结论**：逆光通透**通过了审美筛选**。

### Step 3: direction-selector.md (阶段 1D-2) — "方向分配"

direction-selector 为 🟢现在就拍 应用筛选规则：

```
以下风格永远不会出现在「现在就拍」：
- 需要特定光方向但当前光不满足的（如逆光通透场景当前是顺光）✅ 命中！
→ 逆光通透被排除出「现在就拍」
```

**结论**：逆光通透**被 🟢现在就拍 排除了**。

## 二、冲突在哪？

三条指令在同一个 pipeline 中对同一个风格给出了互相矛盾的判断依据：

| 文件 | 对"逆光通透×顺光"的判断 | 依据 |
|------|------------------------|------|
| style-router | 不排除，🟡标注 | "规则从排除变标注" |
| aesthetic-assertion | 不排除 | "没有审美冲突" |
| direction-selector | **排除出🟢** | "需要特定光方向但当前光不满足" |

**冲突不在结果——在于判断依据。**

- style-router 说：**光线不匹配不是排除的理由**（只标注）
- direction-selector 说：**光线不匹配正是排除的理由**（永远不会出现在🟢）
- aesthetic-assertion 说：**排除应该基于审美，不是技术**

这三个模块用同一个词"排除"说了三件不同的事。AI 在 pipeline 中收到的是三个相互矛盾的指令集——没有协调协议告诉它如何处理这种冲突。

---

## 三、问题根源："排除"一词的多重含义

追踪每个文件对"排除"的实际语义：

| 文件 | "排除"的实际含义 | 合理吗？ |
|------|-----------------|:--:|
| style-router | "从全局发现池中删除"（= AI 搜不到这个风格） | ✅ 合理——v2.1 的核心创新就是不做预过滤 |
| aesthetic-assertion | "从审美方向中移除"（= 这个方向与洞察冲突） | ✅ 合理——审美判断应该排除 |
| direction-selector | "不放入这个方向标签"（= 🟢不显示，但还是可以在🔥或✨中） | ✅ 合理——但现在用了"永远不会出现"这个词 |

**三个操作都合理，但用的是同一个词"排除"，而 AI 无法区分这三种"排除"的边界。**

---

## 四、修复方案

### 方案：三级术语分离 + 显式协调协议

把三个操作改名为不同的概念，永不再混用"排除"一词：

```
第一级 (style-router):     "全量发现" (Discovery)
                            → 完全不做减法。输出 = 所有发现的风格 + 标注

第二级 (aesthetic-assertion): "审美筛除" (Aesthetic Gate)
                            → 只筛除与洞察冲突的方向。依据 = 审美判断（"不应该"）

第三级 (direction-selector): "方向分配" (Routing)
                            → 不"排除"任何东西。只是把风格分配到三个桶：
                              🟢 = 可执行性最高的
                              🔥 = 辨识度最高的
                              ✨ = 创意最酷的
                            → "不出现在🟢" ≠ "被排除"，只是被分配到了另一个桶
```

### 需要修改的具体位置

**style-router.md §六 (L420-431)**: 将"冲突处理"表改名，措辞调整：

```diff
-| 光线物理不完全匹配 | **诚实标注** | 标注优先 |
+| 光线物理不完全匹配 | **诚实标注**（不做减法——全量保留在发现池中） | 发现优先 |

-| 审美冲突 | **不排除** | 最低 |
+| 审美冲突 | **保留在发现池中**（由审美主张引擎决定是否筛除） | — |
```

**direction-selector.md §三 (L96-102)**: 将"排除规则"改为"路由规则"：

```diff
-### 排除规则
-以下风格**永远不会**出现在「现在就拍」：
+### 路由规则——什么风格进入🟢现在就拍
+以下风格**分配给🔥最出片或✨脑洞大开**（不进入🟢）：
 - 需要特定光方向但当前光不满足的（如逆光通透场景当前是顺光）
+  → 这些风格没有被"排除"——它们在🔥或✨的候选池中。
+  → 🟢的职责是"零门槛"，不是"唯一正确答案"。
```

**aesthetic-assertion.md §Step 5 (L171-183)**: 与 direction-selector 的边界声明：

```diff
 Step 5: 排除决策
+  
+  注意：本步骤的"排除"只基于审美判断（"不应该"），
+  不做技术可行性判断。技术可行性由 direction-selector 
+  在方向分配阶段处理——一个在技术上受限的风格会从🟢
+  路由到🔥或✨，而不是被删除。
```

### 新增：协调协议（写入 `_index.md` 或 SKILL.md §1D）

在阶段 1D 之前增加一段协调说明：

```
🔄 三级协调协议：

1. style-router 的"全量发现"不做减法。
   → 输出给审美主张引擎的是一份完整风格清单（含标注）。

2. aesthetic-assertion 的"审美筛除"只筛审美冲突。
   → 筛除条件：洞察冲突 / 统一性破坏 / 叙事断裂。
   → 不禁筛：光线不匹配 / 设备不够 / 需要等待。（这些是方向分配的事）

3. direction-selector 的"方向分配"不做删除。
   → 🟢 不适用 ≠ 风格被排除。它仍在🔥和✨的候选池中。
   → 三个方向共享同一个全局候选池，只是每个方向从池中取不同的子集。
   → direction-selector 的输出格式改为：
     {
       "🟢现在就拍": [从池中选出的可执行性最高的],
       "🔥最出片":   [从池中选出的辨识度最高的],
       "✨脑洞大开": [从池中选出的创意最酷的],
       "其他发现":   [池中未被三个方向选中的——仍可供用户探索]
     }
```

---

## 五、总结

| 问题 | 修复 |
|------|------|
| 三个文件用同一个词"排除"说三件不同的事 | 改为三个不同术语：全量发现 / 审美筛除 / 方向分配 |
| style-router 说"不排除"，direction-selector 说"排除"，AI 收到的指令互斥 | 新增协调协议明确三级之间的数据流向和各自的边界 |
| direction-selector 的"永远不会出现"使 AI 理解为硬删除 | 改为"不分配给🟢，保留在🔥/✨候选池中" |
| 缺少阶段间的数据保留声明 | "其他发现"字段保留未被三个方向选中的风格 |
