## 二、逐模块优化方案

### ① 豆包视觉 API — 从"描述"到"观察+证据"

**当前问题**：
- 观察、推测、感受混在同一段文字里
- `color.mood` 自由文本过于雷同（5/9 张="清新"）
- `weather_env` 未经 EXIF 交叉验证直接使用
- 下游洞察引擎无法区分"照片里真的有什么"和"豆包觉得怎样"

**优化方案**：

1. **Prompt 增加观察/推测标记指令**

```
对于每个字段，请区分层级：
- [观察]：照片中能直接看到的视觉事实
- [推测]：从视觉线索推断的结论（需标注"可能"）
- 不要输出纯感受描述——那是下游的工作
```

2. **`color.mood` 改为三维结构化输出**

```json
"color": {
  "primary": "最主导的颜色",
  "secondary": "次要色",
  "accent": "强调色",
  "mood_axes": {
    "warmth": 0.6,      // 0=极冷, 1=极暖
    "energy": 0.3,       // 0=死寂, 1=爆裂
    "complexity": 0.5    // 0=单色, 1=万花筒
  }
}
```

三个数值组合 ≠ 一个文学词。mood-router 可以基于数值做路由。

3. **增加 `uncertainty` 标记**

```json
"light": {
  "direction": "顺光",
  "quality": "软光",
  "color_temp": "中 — 约5400K",
  "special": "无特殊",
  "uncertainty": "quality"  // ← 标出哪个判断最不确定
}
```

这个标记告诉下游：在 EXIF 交叉验证时优先复查光质。

4. **EXIF 交叉验证后定稿（在 1B 阶段执行，不在 1A）**

```
交叉验证项：
  光质 → ISO + 快门速度 + 亮度值 + 闪光灯状态
  天气 → 实际天气数据(wttr.in) vs 豆包 weather_env
  时段 → 太阳高度角 vs 豆包 color_temp
  场景类型 → GPS地点类型 vs 豆包 scene_type

验证后动作：
  一致 → 定稿
  不一致 → 以 EXIF/物理数据为准，标注"豆包判断为X，物理数据指示Y"
  豆包uncertainty标记的字段 → 强制复查
```

### ② WebSearch 风格搜索 — 优先级 + 权重 + 诚实

**当前问题**：
- 5-7 路无优先级，同等对待
- 搜索结果无权重区分
- 搜不到就编

**优化方案**：

**优先级分层**（不是全搜，按场景触发）：

```
第一梯队（必搜）：
  #1: "{场景一句精准描述} {光线特征} photography style"
      → 覆盖面最广，最直接的风格参考
  #6: "{地点名} {题材} 最佳拍摄方式" ← 有GPS时必搜
      → 地点让搜索从"这类场景"变成"这个具体地方"

第二梯队（有明确触发条件）：
  #2: "{题材} {光线} photography technique composition 中文" 
      → 补充中文社区操作经验
  #3: "{标志性场景元素} photographer portfolio reference"
      → 仅当场景有标志性元素时触发（古塔/雪道/连廊/球场——不是普通河岸/普通客厅）

第三梯队（场景特定，默认不搜）：
  #4: "{场景} mobile photography creative technique"
      → 仅当设备有特殊约束或优势时
  #5: "{场景} editorial fashion photography"
      → 仅当 people≥1 且场景有控光潜力
  #7: "{地点名} {popular_styles} photography"
      → 仅当位置丰富度=高
```

实际执行时大多数场景 2-4 路，不是 5-7 路全搜。

**来源权重**：

```
🏋️ 高权重：
  - 专业摄影教程/杂志（fstoppers/DPReview/Photography Life等）
  - 摄影师个人作品集/画廊档案
  - 社交平台高粉博主（小红书/Instagram ≥10万粉）分享的拍摄教程
  - 高赞高收藏帖子（≥5000赞或收藏）← 大众审美验证 = 对用户最有价值

⚖️ 中权重：
  - 普通社交帖子（<500赞）
  - YouTube 摄影教程
  - 知乎摄影话题回答

📎 低权重：
  - 内容农场
  - AI 生成的内容
  - 泛泛的"N个技巧"列表

权重不决定是否使用——决定引用信心。
高权重 → 方案中可以引用具体摄影师/技法名/帖子
低权重 → 仅作灵感方向，不在方案中引用来源
```

**诚实机制**：

```
搜索后质量自检（在 Step 2 标注前）：

每路搜索：
  🟢 = 返回具体、可操作的信息
  🟡 = 有相关信息但不够具体
  🔴 = 无结果或完全无关

综合判断：
  ≥2路🟢 → 正常流程
  全部🟡 → 缩减推荐数量，标注"基于场景分析，非搜索结果"
  全部🔴 → 诚实告知，只输出规则匹配结果

用户感知（阶段 2 洞察卡片下方）：
  全部🔴时：
  > 这次主要基于场景特征分析——没搜到这个场景的公开参考。
  > 下面的方向来自摄影原理，不是网络热门。

  全部🟡时：
  > 网上关于这个场景的参考不多。方向主要基于场景本身的特点。
```

### ③ WebSearch 技法搜索 — 风格后触发 + 诚实

**当前问题**：
- 与风格搜索并行，但应该是先后关系
- 没有优先级和权重
- 搜不到就编

**核心逻辑修正**：

```
正确流程：

Step A: 风格搜索 → 匹配到合适风格
  ↓
Step B: 在此风格下搜索技法
  #T1: "{风格名} {场景} 拍摄技巧 手机摄影"
  #T2: "{style} {scene} in-camera technique composition posing"
  #T3: "{风格名} {构图/用光/姿势引导的弱项}" ← 针对性补强
  ↓
Step C: 技法融入方案（风格不变，技法丰富执行细节）

风格搜索失败 → 风格无法确定
  ↓
Step B'（备用路线）: 从技法出发
  #T1: "{场景} 创意拍摄 角度 构图 惊喜"
  #T2: "{scene} unexpected angle composition technique"
  ↓
Step C': 技法驱动方案（不标注风格名，只给拍法建议）
```

**诚实机制**：与风格搜索相同——搜不到就诚实说，不编。

**展示原则**：风格和技法在最终方案中不分家。用户看到的是一份完整的口语化拍摄方案——不需要知道哪个来自风格搜索、哪个来自技法搜索。

### ⑤ 审美主张引擎 — 已在测试反馈中讨论

核心改动方向（不再展开）：

1. **insight 去模板化**：打破"最动人的不是X——是Y"句式，给3种叙事策略轮换
2. **洞察必须有视觉锚点**：一个能在照片里指出的具体东西，不能全是抽象情绪
3. **在场感受+场景生态**：产出信息量不足时，洞察可以更短更精准
4. **方向类型扩展**（新增选项，不做硬限制）：

```
现有五种：放大 / 呼吸 / 转移 / 反转 / 致敬

新增选项：
├─ 等待：不现在拍——等光线/天气/人物状态变化
│   例："等她伸手去拿茶杯的那一刻——现在还不是决定性瞬间"
├─ 减法：不是加什么，是去掉什么
│   例："把画面里所有不是米白色和绿色的东西排除掉——只留她和草地"
├─ 借位：利用场景中现成元素制造视觉错觉
│   例："让拱形门洞的弧线刚好框住她——不需要加道具，门就是你的天然画框"
├─ 并置：把两个不相干的东西放在同一个画面里
│   例："黑胶唱机和她的茶杯——两个时代的物件在同一个画面里安静共存"
└─ 负空间：不拍主体，拍主体周围的空白
    例："不拍她——拍她走后那个还热着的茶杯"
```

不给硬规则（"必须覆盖N种类型"）。有好的方向就给，没有就不给。没东西时诚实说——方向卡片可以只有🟢和🔥两屏，✨可以不展示。

### ⑥ 方向选择卡片 — 诚实优先

**核心原则**：

```
🟢 现在就拍：每个场景都有。再平淡，站在这就能拍——这是底线。

🔥 最出片：不是每个场景都有。
  有 → 展示
  没有 → 诚实：「这个场景更适合简单记录，不需要追求"出片"」

✨ 脑洞大开：更不是每个场景都有。
  有（真正的观看方式变化）→ 展示
  没有 → 不展示这一屏。不要为了凑数硬编大师名字。
```

**💬 推荐理由调性**：

```
有话则长无话则短。
场景条件好 → 口语化粗体多写两句，帮用户感受
场景条件一般 → 一句话说清楚：「站在这，这样拍，就可以了」
硬说空洞的话 → 比不说更差
```

### ⑦ 方案生成 — 弹性数量 + 组图触发

**场景评估**（方案生成前的快速判断）：

```
🥉 一般场景（普通客厅/随手拍/信息量少）
   → 1-3 套方案
   → 让用户快速拍一张满意的就走
   → 不强凑差异化

🥈 不错场景（有光线/构图/情绪亮点）
   → 3-6 套方案
   → 正常差异化维度

🥇 丰富场景（空间层次深/人物状态好/光线有戏剧性/元素密集）
   → 6-9 套方案（上限 9 张——适配朋友圈九宫格）
   → 启用组图节奏（series-rhythm）：
     "这是一个值得慢慢拍的地方。按这个顺序来——"
     全景·她在空间里 → 中景·她在做这件事 → 近景·她的手 → 特写·留下的痕迹
```

**🎯 换个思路**：有真正的观看方式变化才写。没有就不写。不凑数。

**诚实兜底**：如果场景真的不适合拍（光线极差/场景杂乱无序/没有可构图的空间）→ 诚实告知：「这个场景目前的光线和环境不太容易出片。建议换个时间（如黄金时刻）或换个位置。如果想现在拍，这是最简单的方式——」

### ⑧ 豆包生图提示词 — 精简 + 前期优先

**三层效果重新排序**：

```
📷 原图能拍 → 核心推荐。画面效果主要来自前期（构图/角度/焦段/时机）
🖌️ 前期手法 → 可以推荐。手机自带滤镜/富士胶片模拟/相机内置风格/网格/水平仪
🖌️ 后期加工 → 仅在风格确实需要时加入（如胶片色/黑白转换/色温偏移）
🤖 AI生图 → 默认不出现。仅在真正能帮用户打开思路时展示
            → 展示时必须明确标注"这是AI生成的效果，不是拍出来的"
```

**删除**：关键词解读（📋 5个关键词的中文解释）

### ⑨ 审美验证 — 从打分到结构化自检

**当前问题**：AI 给自己打分永远 7-8 分，1-10 分没有校准基准，形同虚设。

**改为**：方案生成后的内部自检清单（不打分，追问四件事）：

```
□ 这套方案有清晰的视觉叙事吗？不只是"站这里按快门"
□ 色调/影调/质感在选定风格框架内吗？有没有跑偏
□ 排除了不该出现的东西吗？排除有理由吗
□ 有破格吗？有的话是有意为之吗？意是什么
```

不通过的不是"分数不达标"——是逻辑矛盾被发现（如"森系方案用了高反差黑白"）。

## 三、AI 模块精简分析

### 3.1 当前模块清单

| # | 模块 | 调用方式 | 每次消耗 | 必要性 |
|:--:|------|------|:--:|:--:|
| 1 | 豆包视觉 API | 外部 API | 1 次 | 🔴 不可替代 |
| 2 | WebSearch 风格搜索 | 外部搜索 | 2-7 次* | 🟡 可精简 |
| 3 | WebSearch 技法搜索 | 外部搜索 | 2-4 次* | 🟡 条件触发 |
| 4 | AI 综合判断 | LLM 推理 | 1 次 | 🟡 与⑤重叠 |
| 5 | 审美主张引擎 | LLM 推理 | 1 次（5步） | 🔴 核心创意 |
| 6 | 方向选择卡片 | LLM 生成 | 1 次 | 🟢 需要但可精简 |
| 7 | 方案生成 | LLM 生成 | 1-4 次** | 🟢 弹性 |
| 8 | 豆包生图提示词 | LLM 生成 | 0-1 次*** | 🟢 默认不生成 |
| 9 | 审美验证 | LLM 自评 | 1 次 | ❌ 改为内置自检 |

\* 搜索次数已通过优先级分层减少  
\** 方案按需生成（用户点"下一套"才生）  
\*** 改成默认不触发

### 3.2 可合并的模块

**④ AI综合判断 + ⑤ 审美主张引擎 → 合并**

理由：
- 两者都是 LLM 读取搜索结果 → 产出判断
- ④输出`discovered_styles`和`scene_insight`，⑤也产`insight`和`creative_directions`
- 目前④的`scene_insight`和⑤的`insight`是什么关系？设计文档没有明确——这是同一件事被做了两次

合并后流程：
```
搜索完成 → 一个完整的 LLM 推理过程：
  1. 从搜索结果中提取风格方向（原④）
  2. 沉浸场景+提炼洞察（原⑤ Step 1-2）
  3. 从洞察生长创作方向（原⑤ Step 3）
  4. 设备翻译（原⑤ Step 4）
  5. 审美筛除（原⑤ Step 5）
  
  输出：洞察 + 创作方向列表 + 风格匹配结果
  → 传递给方向选择器
```

**⑨ 审美验证 + ⑦ 方案生成 → 内置自检**

理由：
- ⑨是⑦的输出后检查，不是独立步骤
- 作为⑦的最后一步内置执行
- 不是打分——是追问+修正

### 3.3 精简后的模块架构

```
阶段 1：场景理解
  ├─ 1A 豆包视觉 API ........................ [外部API, 1次]
  ├─ 1B 题材检测 + EXIF验证 + 设备加载 ....... [规则, 0 API]
  └─ 1C 环境感知汇总 ........................ [汇总, 0 API]

阶段 2：AI 引擎
  ├─ 2A 风格搜索（优先级分层，2-4路）........ [外部搜索]
  ├─ 2B 综合判断（合并④+⑤，含规则标注）...... [LLM推理, 1次]
  │     ├─ 搜索结果→风格匹配+标注
  │     ├─ 场景沉浸→洞察提炼
  │     ├─ 创作方向生长（含技法启发）
  │     ├─ 设备翻译
  │     └─ 审美筛除
  ├─ 2C 技法搜索（条件触发）................. [外部搜索, 0-3次]
  │     ├─ 有风格 → 风格下搜技法
  │     └─ 无风格 → 技法出发搜惊喜
  └─ 2D 方向分配 ........................... [规则, 0 API]

阶段 3：用户交互
  ├─ 3A 方向选择卡片 ........................ [LLM生成, 1次]
  │     └─ 🟢必有 / 🔥按需 / ✨按需（诚实）
  └─ 用户选择方向

阶段 4：方案生成
  ├─ 场景评估（🥉🥈🥇）.................... [规则, 0 API]
  ├─ 方案生成 ............................... [LLM生成, 1-2次]
  │     ├─ 生成方案（弹性数量 1-6套）
  │     └─ 内置自检（原⑨，不打分，追问修正）
  └─ 生图提示词（默认不生成）................ [0次]

阶段 5：知识沉淀 ............................ [静默, 0 API]
```

### 3.4 效率对比

| 指标 | v3.3（当前） | v4（优化后） | 节省 |
|------|:--:|:--:|:--:|
| 每次搜索调用 | 7-11 次 | 2-7 次 | ~40-50% |
| LLM 推理步骤 | 4-5 次独立调用 | 2-3 次 | ~40% |
| 生图提示词生成 | 每套方案必出 | 默认不出 | ~95% |
| 方向卡片 | 3 张全出 | 1-3 张按需 | 0-66% |
| 方案套数 | 3-4 套（硬凑）| 1-6 套（弹性）| 场景决定 |
| 核心路径 token 估算 | ~8-12K | ~4-7K | ~40-50% |

**最大的效率提升不来自合并模块——来自三件事**：

1. **搜索不再全搜**：大多数场景 3-4 路搜索就够了（不是 7-11 路）
2. **没东西就诚实不说**：不编内容 = 不消耗 token 编造
