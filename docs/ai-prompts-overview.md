## <a id="1">① 豆包视觉 API — 识图提示词</a>

**位置**: `SKILL.md` L371-416 | **调用方式**: 豆包 API (`doubao-seed-2.0-pro`)

### 提示词（隐含——通过输出格式约束驱动）

AI 没有被给一段"请描述这张照片"的文本提示词。它被要求输出一个特定的 JSON 结构。AI 必须通过理解这个 schema 来理解"我需要从照片中提取什么"。

```
你必须输出一个结构化 JSON，包含 8 个字段，缺一不可：

{
  "scene_type": "室外/室内/半室外 — 具体场景描述",
  "people": "人物数量、每人位置/衣着/动作/表情/姿态",
  "light": {
    "direction": "顺光/侧光/逆光/顶光/漫射",
    "quality": "硬光/软光/混合",
    "color_temp": "暖/中/冷 — 估算K值",
    "special": "遮阳阴影区/斑驳树影/窗边漫射/混合色温"
  },
  "color": {
    "primary": "最主导的颜色",
    "secondary": "次要色",
    "accent": "强调色",
    "mood": "整体色彩情绪"
  },
  "space": {
    "foreground": "前景有什么",
    "midground": "中景有什么",
    "background": "背景有什么",
    "depth": "浅/中/深"
  },
  "composition": "当前构图方式 + 可利用的构图元素",
  "perspective": "拍摄视角 + 机位高度描述",
  "weather_env": "天气状况 + 环境细节"
}
```

### 你和这个提示词的关系

- **你控制的东西**: 8 个字段的维度和分类体系（如 light.direction 只能选 5 种之一）
- **AI 自主发挥的东西**: 每个字段的具体内容描述（如"最主导的颜色"=AI 自己判断）
- **可能不符合预期的地方**: 
  - `color.mood` 太主观——"整体色彩情绪"在不同 AI 模型间差异大
  - `light.direction` 有时很难判断单一方向（漫射光就没有方向）
  - `special` 字段是自由文本，AI 可能漏掉或过度描述

## <a id="2">② WebSearch — 风格搜索（5-7 路并行）</a>

**位置**: `SKILL.md` L514-541 + `style-router.md` L310-329 | **调用方式**: WebSearch 工具

### 搜索模板

```
并联 5-7 路，不预设排除条件：

#1: "{场景一句话描述} {光线特征} photography style inspiration best approach"
    → 目标：全球范围内的风格参考

#2: "{题材} {光线条件} {情绪氛围} 摄影 风格 怎么拍 最佳"
    → 目标：中文社区的实际拍摄经验

#3: "{类似场景元素} photographer portfolio reference style"
    → 目标：找到拍过类似场景的摄影师和他们的风格

#4: "{场景关键词} {设备类型} mobile photography creative technique"
    → 目标：设备特定的创意技法

#5: "{场景} {光线} editorial fashion photography style"
    → 目标：时尚/商业摄影的风格参考

#6: "{地点名} {题材} 最佳拍摄方式 {光线特征}"  ← 如有位置上下文
    → 目标：这个具体地点的最佳拍法——将位置情报与场景融合

#7: "{地点名} {popular_styles} photography"  ← 如有位置上下文+当地流行风格
    → 目标：这个地点最流行的风格的全球参考
```

### 你和这个提示词的关系

- **你控制的东西**: 搜索方向的数量和分类（全球/中文/摄影师/设备/时尚/地点）
- **AI 自主发挥的东西**: 
  - 模板里的 `{变量}` 填什么——AI 根据豆包视觉识别的结果来填
  - 搜索结果回来后，哪些算"好的匹配"——AI 综合判断
- **可能不符合预期的地方**:
  - #4 和 #5 的区分不清晰——"mobile photography creative technique"和"editorial fashion"可能返回同类内容
  - 搜索结果质量完全取决于搜索引擎返回什么，AI 只能"综合"
  - 如果所有搜索都返回无关内容，AI 现在没有"诚实告知用户搜索失败"的机制——会硬编

## <a id="3">③ WebSearch — 技法搜索（2-4 路并行）</a>

**位置**: `SKILL.md` L543-566 + `technique-router.md` L125-145 | **调用方式**: WebSearch 工具

### 搜索模板

```
并联 2-4 路，与风格搜索同步执行：

#T1: "{场景描述} 拍摄技巧 手机摄影 构图"
    → 目标：中文社区（小红书/知乎/微博）的真实拍摄经验
    → 提取：具体操作步骤 + 场景适配 + 样片特征

#T2: "{scene} portrait composition technique in-camera angle posing"
    → 目标：英文社区（YouTube/Instagram/Pinterest）的创意技法
    → 提取：机位/角度/景别/姿势引导

#T3: "{场景关键词} 创意构图 角度变化 前景遮挡 剪影 视角"
    → 目标：特定技法类型的场景应用
    → 提取：可复用的操作模式

#T4 (如适用): "{匹配的大师名} 拍摄手法 构图方式 前期技巧"
    → 触发条件：仅当 master-router 已匹配到明确的大师参照时
    → 提取：可操作的构图/视角/取景习惯
```

### 你和这个提示词的关系

- **你控制的东西**: 搜索方向和触发条件
- **AI 自主发挥的东西**: 从搜索结果中"获得启发"——不是简单的信息提取，是"看到搜索结果→被启发→生长出创作方向"
- **可能不符合预期的地方**:
  - "被启发"这个环节完全不可控——AI 可能从搜索结果中得到完全无关的"启发"
  - T4 的触发条件"仅当 master-router 已匹配到明确的大师参照时"——AI 可能漏触发或误触发
  - 技法路由的核心承诺"技法融化在方案里"完全依赖 AI 的判断力

## <a id="4">④ AI 综合判断框架 — 搜索结果→发现输出</a>

**位置**: `style-router.md` L331-362 | **调用方式**: LLM（不是外部 API，是 skill 内部的推理指令）

### 提示词（通过输出 JSON schema 约束）

```
搜索完成后，AI 综合判断输出：

{
  "scene_insight": "对这个场景美学潜力的洞察陈述（一句话）",
  "discovered_styles": [
    {
      "name": "风格名",
      "source": "发现来源（URL 或 推理链）",
      "fit_rationale": "为什么这个风格最适合这个场景",
      "visual_effect": "拍出来是什么感觉",
      "technical_requirements": "需要什么技术条件",
      "executability": "🟢/🟡/🟠（在当前设备+光线下的可执行性）",
      "is_new_to_kb": true/false
    }
  ],
  "excluded_styles": [
    {
      "name": "排除的风格",
      "reason": "排除原因（光线冲突/设备不够/审美冲突）",
      "exclusion_type": "physical/device/aesthetic"
    }
  ],
  "knowledge_gap": {
    "detected": true/false,
    "description": "发现的知识空白描述（如检测到）",
    "suggested_action": "建议的采集动作"
  }
}
```

### 你和这个提示词的关系

- **你控制的东西**: 输出结构的字段和分类体系
- **AI 自主发挥的东西**: 每个字段的具体内容——特别是 `fit_rationale`（"为什么适合"）和 `visual_effect`（"拍出来是什么感觉"）
- **可能不符合预期的地方**:
  - `excluded_styles` 的意义现在有歧义（v2.3 已修复——这里应该是"标注但未进入主推荐的风格"）
  - `is_new_to_kb` 要求 AI 知道"知识库里有什么"——但 AI 可能没读完所有知识文件
  - `scene_insight` 和 aesthetic-assertion 的 `insight` 是什么关系？是同一个东西还是两层不同的洞察？

## <a id="5">⑤ 审美主张引擎 — 5 步创意流程</a>

**位置**: `SKILL.md` L694-794 + `aesthetic-assertion.md` L87-183 | **调用方式**: LLM 内部推理

这是整个项目中最"AI 自主发挥"的部分。不是填表——是 AI 的内省过程。

### Step 1: 场景沉浸

```
读取豆包视觉识别的完整场景描述。不是提取特征——是沉浸进去。

问自己：
- 如果我是现场的人，我会被什么打动？
- 这个场景里最安静的那个角落在哪里？
- 什么东西一闪而过就不会再来？

输出：2-3 句"在场感受"——不是技术分析，是人的感受。
```

其次是 **场景生态描述**（v2.1 新增）：

```
从"在场感受"中拆解出四组互动关系：

- 光与物的互动：光打在什么材质上？产生了什么效果？
- 人与空间的互动：人在这个空间里是融入的还是闯入的？
- 色彩与情绪的互动：色彩组合传递了什么感受？
- 时间与状态的互动：这一刻会过去吗？什么东西稍纵即逝？

输出：四组互动关系——每组 1 句。
```

### Step 2: 洞察提炼

```
从"在场感受"中提炼一句话洞察。

洞察的结构："这个场景最动人的是[什么]——因为[为什么]"

✅ 好的洞察：
"最动人的是她和小狗之间安静的信赖——没有任何表演，就是生活本来的样子"
"最动人的是多云天下的河面反光——像一整条银灰色的丝绸"

❌ 坏的洞察（分类标签，不是洞察）：
"这个场景是叙事驱动——因为女人和狗有互动关系"

判断标准：分类回答"它属于哪一类"；洞察回答"它为什么动人"
```

### Step 3: 创作方向生长

```
从洞察的具体元素出发，生长 3-5 个创作方向。

技法灵感注入：本步骤同步读取 1C 技法搜索的结果（technique_discoveries）。

方向类型：
├─ 放大：把洞察中最动人的元素放大到极致（如：只拍手和狗耳朵）
├─ 呼吸：退后让元素在更大空间里呼吸（如：退后把河和天空收进来）
├─ 转移：把核心情感从一个载体转移到另一个（如：拍她们之间的草地）
├─ 反转：把某个参数反转制造全新审美（如：温暖→清冷）
└─ 致敬：用大师观看方式诠释洞察（如：川内伦子微物神圣化）

规则：
- 每个方向必须可直接追溯到洞察中的具体元素
- 方向之间要有真实审美差异（不是同一逻辑微调）
- 至少一个方向是"非显而易见的"（用户自己想不到的）
- 至少一个方向充分利用设备优势（而非对抗局限）
- 至少一个方向从技法搜索的启发中生长出来
```

### Step 4: 设备翻译

```
将创作方向翻译为当前设备上的具体执行方案。

❌ 降级思维："没有长焦→用 2× 裁切凑合"
✅ 优势思维："iPhone 最近对焦距离比相机更近→可以靠得更近→
             这个方向用手机拍反而比相机更有亲密感"
```

### Step 5: 审美筛除（v2.3）

```
基于洞察，筛除一些路线。筛除不是因为"做不到"——是因为"不应该"。

筛除类型：
├─ 洞察冲突：这个路线跟场景最动人的东西背道而驰
├─ 统一性：这个路线会破坏场景天然的审美统一
└─ 设备浪费：这个路线不能用设备优势，反而暴露短板

不经手的事项（交给方向选择器）：
├─ 光线不匹配 → 方向选择器会把它从🟢路由到🔥或✨
├─ 设备能力不足 → 方向选择器会在脑洞大开中标注条件
└─ 时机不对 → 方向选择器会在脑洞大开的"时空假设"中呈现
```

### 你和这个提示词的关系

- **你控制的东西**: 5 个步骤的框架、方向类型的分类、好坏洞察的示例
- **AI 自主发挥的东西**: 几乎全部——这是项目中最"AI-native"的模块
- **最可能不符合预期的地方**:
  1. **"在场感受"可能很空洞** — AI 不在现场，只能从豆包视觉描述的文字中"假装沉浸"。容易产出"温暖的午后，阳光洒在草地上"这种毫无信息量的文字。
  2. **洞察可能退化为分类** — 你给了好坏示例，但 AI 在长文本中容易滑回分类模式。特别是如果前面 WebSearch 没搜到好东西，AI 没有"灵感燃料"。
  3. **创作方向可能变排列组合** — "放大/呼吸/转移/反转/致敬"五个类型是框架。AI 可能机械地对每个场景往五个类型里各塞一个方向，而不是真正从洞察中"生长"。
  4. **技法启发环节没有强制检查** — "至少一个方向从技法搜索的启发中生长出来"是规则，但如果技法搜索没返回好东西，AI 可能假装有一个技法启发了方向。
  5. **设备翻译"优势思维"需要 AI 真正理解设备** — 如果 AI 对 iPhone 能力的理解有偏差，"优势思维"反而变成误导。

## <a id="6">⑥ 方向选择卡片 — 输出格式</a>

**位置**: `SKILL.md` L886-978 | **调用方式**: LLM 生成

### 提示词（通过模板 + 设计原则约束）

核心原则：

```
用户只读两样就能做决定——一段话 + 一行要做什么。
💬 推荐理由：合并钩子+为什么适合，结果承诺开头→中间讲原因→结尾确认选择，一段口语化粗体
📋 怎么做：一句话说完用户需要做什么（或什么都不用做）
专业分析全部折叠在 <details>，想深究的自己展开
删除时间预估、难度等级——没意义的信息不给用户看
```

模板：

```
### 🟢 现在就拍 · {风格名}

**💬 推荐理由**
{一段口语化粗体——结果承诺开头："拍完没人会觉得你刻意拍了照。"
 → 中间讲为什么场景条件天然匹配
 → 结尾确认："现在这样就是答案。"}

**📋 怎么做**
{一行说完——"什么都不用准备——站在这就能拍" 或 具体1-2步}

<details>
<summary>📊 为什么推荐{风格名}（点击展开）</summary>
**风格特征**：{一句话概述风格审美核心}
**这个场景的天然优势**：
- {优势1}
- {优势2}
- {优势3}
**光线评估**：{光线匹配度 🟢🟡🔴 + 说明}
**设备评估**：{设备可执行性 🟢🟡🔴 + 说明}
</details>


### 🔥 最出片 · {风格名}

**💬 推荐理由**
{一段口语化粗体——反直觉开头："阴天拍出来比晴天好看——说真的。"
 → 中间解释为什么这个风格把缺点变优势
 → 结尾给出画面感受}

**📋 怎么做**
{一行说完——"退后3-4米，蹲下，切换到0.5×超广角"}


### ✨ 脑洞大开 · {方向名}

**💬 推荐理由**
{一段口语化粗体——认知升维开头："这不是拍照，是说故事。"
 → 中间解释大师/跨界的观看方式
 → 结尾点出理解了这个就理解了摄影的什么}

**📋 怎么做**
{如实告知需要什么条件。你的设备能做到约X%}

**💡 现在就能试**
{一个小版本——现在就能做，不需要额外条件。即使效果粗糙——但会立刻理解方向的美学逻辑}
```

### 你和这个提示词的关系

- **你控制的东西**: 卡片结构、文案风格方向、三类方向各自的叙事策略
- **AI 自主发挥的东西**: 具体的文案内容——特别是钩子句和语调
- **可能不符合预期的地方**:
  1. **"口语化粗体"的语调不稳定** — AI 可能在"太正式"和"太轻浮"之间摇摆。"拍完没人会觉得你刻意拍了照"这个调性很难每次都踩准。
  2. **💬推荐理由可能变模板** — 虽然你给了不同方向不同的叙事策略（🟢=结果承诺/🔥=反直觉/✨=认知升维），但 AI 用多了可能退化："拍完你会发现..." / "这个场景最绝的是..." 反复出现。
  3. **脑洞大开的"X%"数字是 AI 编的** — 在之前的审查中已经指出。

## <a id="7">⑦ 方案生成 — 输出格式</a>

**位置**: `SKILL.md` L1080-1155 | **调用方式**: LLM 生成

### 提示词

核心约束：

```
所有方案统一在用户选定的风格下。
方案按"从易到难"排列——方案 1 永远是最容易执行的那套。

风格一致性：色彩/光质/质感参数与选定风格一致。
差异化检查：构图方式不重复、景别不重复、人物状态有变化。

不强凑 4 套——场景只有 3 个有效构图方式就出 3 套。
```

差异化维度表：

```
| 维度 | 方案 1 | 方案 2 | 方案 3 | 方案 4 |
|------|--------|--------|--------|--------|
| 构图 | 三分法 | 前景虚化 | 留白构图 | 引导线/框架 |
| 景别 | 中景 | 近景/特写 | 远景 | 创意角度 |

| 人物状态 | 看镜头 | 不看镜头 | 互动/动作 | 纯场景（无人物）|

不是机械填表——根据实际场景选择最有意义的差异化组合。
```

### 你和这个提示词的关系

## <a id="8">⑧ 豆包生图提示词 — 输出规范</a>

**位置**: `SKILL.md` L1502-1617 | **调用方式**: LLM 生成（不直接调生图 API，只生成文本给用户复制）

### 核心约束

```
1. 以用户照片为参考基础——不随意发挥创造新场景
2. 只有 EXIF/搜索确认的内容才能加入——不能虚构
3. 不描述人脸特征——不出现"大眼睛""高鼻梁""尖下巴"
4. EXIF 作为事实边界——不能把闪光灯说成自然光、夏天说成秋天
5. 所有非原图手段必须声明——后期/道具/设备改变都要标注
```

### 三层标注系统

```
🟢 原图能拍（📷 原图）：换个构图/角度/焦段就能实现
🟡 简单后期可实现（🖌️ 后期）：调色/裁剪/加颗粒/柔焦，标注具体 app 和操作
🟠 需要 AI 生图（🤖 AI生图）：改光线方向/季节/景深/加元素，标注"原图拍不出来"
```

### 输出模板

```

| 效果 | 怎么实现 |
```

### 你和这个提示词的关系

- **你控制的东西**: 三层标注体系、诚实声明标准、输出结构
- **AI 自主发挥的东西**: 英文技术化描述的写作、关键词的选择和解读
- **可能不符合预期的地方**:
  1. **英文提示词质量波动** — 豆包生图模型对英文提示词的响应方式可能不同于 Midjourney/Stable Diffusion，格式可能需要针对豆包调整
  2. **三层标注可能被滥用** — AI 可能为了显得"诚实"而把所有效果都标成🤖，或者反过来把 AI 才能做到的效果标成🟡后期

## <a id="9">⑨ 审美验证 — 四维批判</a>

**位置**: `SKILL.md` L1228-1249 | **调用方式**: LLM 自评

### 提示词

```
对每套方案评分（1-10）：

叙事完整性：方案是否有清晰的视觉叙事？
  构图/光线/情绪是否统一服务于一个表达意图？ 合格线 ≥ 6

调性统一度：色彩/光线/质感是否在选定的风格框架内？
  是否存在风格不一致的元素？ 合格线 ≥ 6

取舍合理性：方案是否明确排除了不该出现的元素？
  排除决策是否有审美依据（而非纯技术限制）？ 合格线 ≥ 6

破格目的性：如果有打破规则的地方，是有意为之还是技术失误？
  破格是否服务于统一的情绪目标？ 合格线 ≥ 6（无破格时N/A）

不通过处理：
  某个维度 < 6 → 标记"建议调整"
  ≥ 2 个维度 < 6 → 方案重新生成
```

### 你和这个提示词的关系

- **你控制的东西**: 四个维度的定义和合格线
- **AI 自主发挥的东西**: 1-10 的打分——但这是**自我评分**
- **最可能不符合预期的地方**:
  1. **AI 给自己打分天然偏高** — 刚写出来的方案，AI 倾向于给 7-8 分。很少会出现 < 6。
  2. **1-10 分没有任何校准基准** — AI 今天打的 6 分和明天打的 6 分含义可能完全不同
  3. **"方案重新生成"可能死循环** — 如果 AI 连续两次打出 < 6，第三次大概率也差不多。没有最大重试次数限制。
