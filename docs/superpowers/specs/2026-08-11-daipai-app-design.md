## 0. 一句话定位

**带拍不是 AI 相机，是装在口袋里的摄影师——它给你方案，相机是你自己的，它把方案"编译"进取景器，让你边看边拍，拍完直接在 APP 里修到方案预期。**

这是 Iron Man 套装，不是 Iron Man 机器人：人始终握着快门和审美判断，AI 是抬头显示器。

## 1. 目标与非目标

### 1.1 v1.0 目标

1. **完美融入现有带拍能力**：视觉识别 → 三方向（🟢现在/🔥最出片/✨最大胆）→ N 套方案（subject/shooter/gear/enhance + result/why/quick_edit）全部可用，后端零改造复用。
2. **原生相机能力全开**：手动控制（ISO/快门/白平衡/对焦/曝光补偿）、RAW/ProRAW、焦段切换、网格/水平仪、深度人像。
3. **方案进相机**：方案的站位、机位、焦段、曝光、光线时机以取景器叠加层呈现，用户不离开相机就能跟拍。
4. **细致后期**：非破坏性编辑栈，覆盖基础调节 + 方案 quick_edit 一键落地为可调节预设。
5. **数据飞轮**：回流"看了哪个方案、实际拍没拍、用了什么参数、后期怎么调"，反哺方案质量。

### 1.2 非目标（v1.0 不做）

- 不做 Halide 级自定义 Metal 渲染管线、focus peaking、48MP ProRAW 全功能 → v2.0
- 不做 HSL/曲线/锐化降噪/局部调整 → v1.5
- 不做图生图直接出图（保持生成 Seedream 提示词、一键跳转豆包）
- 不做安卓中低端机的手动/RAW（LEGACY 设备回退系统相机 + AI 方案）
- 不做社区/短视频/社交 feed（v2.0 后评估）
- 不做订阅付费系统（v1.0 沿用配额制，后续再做商业化）

## 2. 目标用户与核心场景

### 2.1 用户画像

- **主力**：18-30 岁女性，爱拍照发小红书/朋友圈，用 iPhone（Pro 占比高），会用醒图/VSCO/Lightroom Mobile 但觉得"参数看不懂"或"不知道怎么摆、怎么找角度"。
- **痛点**：不是不会修图，是**前期拍不好**——男朋友/同伴拍不出想要的感觉、自己一个人旅行没人拍、看到好看的场景不知道怎么下手。
- **她们不要**：冷冰冰的专业参数轰炸、粉粉嫩嫩的幼稚美颜风、又一个滤镜 APP。
- **她们要**：有人"带"着拍、有审美品味、结果能直接发、过程不费劲。

### 2.2 核心场景

| 场景 | 当前（Web） | APP v1.0 |
|---|---|---|
| 和同伴出门，想拍出片 | 拍一张→等2分钟→看方案→切系统相机→凭记忆拍 | 取景器里直接有站位框/焦段刻度，边看边拍 |
| 一个人旅行自拍 | 放手机架，盲拍 | 方案告诉你机位/高度/倒计时，姿态引导叠加 |
| 日落/蓝调时刻 | 看文案提醒 | 取景器顶部金色进度条 + 震动提示时机 |
| 拍完想调色 | 跳 VSCO/LR 手调 | quick_edit 直接变成预设，滑块已摆好，微调即出片 |
| 想 AI 换景 | 复制提示词到豆包 | 一键复制 + 跳转豆包 APP，体验更顺 |

## 3. 技术选型

### 3.1 选型结论

| 层 | 技术 | 理由 |
|---|---|---|
| APP 框架 | **React Native 0.74+**（New Architecture） | 团队有 2400 行原生 JS 经验；后端 Python 零改造复用 |
| 相机 | **react-native-vision-camera v4** | 已验证支持手动控制/RAW/ProRAW/Frame Processors（独立 JS 线程逐帧），plugin 生态成熟 |
| 叠加层渲染 | **react-native-skia**（Shopify） | GPU 加速、跨端一致，画对焦框/网格/直方图/后期预览 |
| 端侧 AI | **ML Kit + TensorFlow Lite** | 人脸/场景分类/亮度直方图，不上传画面 |
| 后期引擎 | **Skia ColorMatrix/ImageFilter**（一期跨端）+ iOS Core Image 桥接 ProRAW 解码 | 基础调节双端一致；RAW 走原生 |
| 本地数据库 | **react-native-quick-sqlite** | 与现有 SQLite schema 对齐，会话/作品/编辑历史本地存 |
| 导航 | **React Navigation 6** | 类型安全、原生转场 |
| 状态 | **Zustand** | 轻量，不引入 Redux 复杂度 |
| 后端 | **现有 Flask 不动**，新增 `/app/*` 路由 | 视觉豆包 Lite / 方向方案 DeepSeek Flash 全部复用 |
| 鉴权 | Apple Sign In（iOS）+ 微信登录（安卓/国内） | JWT，替代 Web 端 IP 配额 |

### 3.2 被否决的方案

- **Flutter**：`camera_awesome` 手动控制有但 RAW/DNG 支持不明确，逐帧 AI plugin 生态弱于 VisionCamera。摄影 APP 对相机管线控制深度要求高，此项劣势致命。
- **原生双端（Swift + Kotlin）**：质量天花板最高（Halide 路线），但双端成本翻倍，团队无原生基础，v1.0 周期不可接受。v2.0 若做专业级渲染再评估。
- **纯 PWA**：Web 端已是 PWA-ish，但 PWA 无法调用手动控制/RAW/Frame Processor，做不到核心差异化。

### 3.3 关键工程原则（Karpathy 视角）

- **March of Nines**：iOS 优先 + 安卓旗舰，LEGACY 设备优雅降级，不在低端机追 Halide 体验。
- **数据飞轮 > 模型架构**：APP 埋点回流真实拍摄数据，这是 Web 端做不到的护城河。
- **Don't be a hero**：后端不重写、视觉模型不换、能用 Skia 跨端就不写双端原生。
- **锯齿状智能**：端侧 AI 会犯蠢，所有 AI 判断都给用户"看错了，手动来"的逃生口。

### 4.1 原生模块边界

需要写的原生/桥接代码（量很小）：

1. **ProRAW 解码模块（iOS）**：VisionCamera 拍出 `.dng`，用 Core Image `CIRAWFilter` 解码为位图，送入 Skia 编辑管线。Android 端 RAW 用 LibRaw 或仅在 FULL/LEVEL_3 设备开放。
2. **端侧场景分类 Frame Processor Plugin**：封装 TFLite 模型为 VisionCamera frame processor plugin（Swift/Kotlin 各一层薄壳，推理走库）。
3. **亮度直方图/zebra**：可在 JS frame processor 里算（取像素亮度），性能不够再下沉原生。
4. **文件导出**：编辑栈烘焙为 JPEG/HEIC（iOS 用 ImageIO，Android 用 Bitmap）。

其余全部 JS/TS + Skia。

## 5. 功能模块详细设计

### 5.1 模块 A：AI 方案大脑（接入现有后端）

**基本复用**，APP 端做三件事：

1. **更快的上下文采集**：EXIF/GPS/设备型号直接从系统 API 取（比 Web 端 exiftool subprocess 快），随照片上传。
2. **SSE 渐进式 UI**：复用现有四阶段事件（exif_ready → vision_ready → directions_ready → plans），APP 端用奶油风动画呈现。
3. **会话同步**：本地 SQLite 缓存会话，24h 内可恢复；成片反馈回流 `/app/sync`。

新增后端路由：

| 路由 | 方法 | 作用 |
|---|---|---|
| `/app/auth` | POST | Apple/微信登录换 JWT |
| `/app/session` | POST | 上传照片（含 RAW 分片）+ EXIF/GPS，返回 session_id，走现有 SSE |
| `/app/presets` | GET | 拉取 39 风格预设 + 方案 quick_edit 参数 |
| `/app/sync` | POST | 回流拍摄结果（选了哪个方案、实际拍摄参数、👍👎、编辑参数） |

### 5.2 模块 B：带引导的相机（核心差异化）

#### 5.2.1 四层引导体系

**第 1 层 · 取景器叠加层（always-on，可一键关）**

用 Skia 在相机预览上画半透明图形，不挡脸、不抢焦点：

| 方案字段 | 叠加层表现 |
|---|---|
| `subject`（被摄者站位） | 暖金色人形轮廓/定位框，透明度 15-25%，描边 1px 实线 |
| `shooter`（机位/角度） | 目标俯/仰角时，取景器边缘淡入暖金辉光；水平仪变金色 |
| `gear`（焦段） | 变焦滚轮滑到推荐焦段时**震动 + 减速吸附**（UIImpactFeedbackGenerator light） |
| `gear`（曝光） | EV 滑杆推荐值处有暖金刻度点；过曝区域实时 zebra 斑马纹（半透明白斜纹） |
| `enhance`（光线/前景） | 关键提示以 1-2 字小标签浮在对应区域（如"补光""低一点"） |
| 构图 | 三分线/黄金螺旋/中心框，按方案切换，暖金 0.3 透明度 |
| 光线时机 | 顶部 2px 金色进度条（日落倒计时），<15min 时轻微脉动 |

**第 2 层 · 方案卡浮层（单击屏幕呼出，不离开相机）**

- 顶部：方案名 + `result` 一句话画面预览
- 中间：subject / shooter / gear / enhance 四段，每段一行，点开展开
- 底部：方案横滑条（"换个方案"），滑动时**叠加层实时切换**（构图框、焦段刻度、参数建议跟着变）
- 右上角"收起"回到纯取景器

**第 3 层 · 实时场景检测（Frame Processor，端侧，不上传）**

- 亮度直方图（每帧）→ zebra + EV 建议
- 人脸检测（ML Kit）→ 提示人像模式/推荐焦段/人脸构图
- 场景分类（TFLite 轻量模型）→ 命中 street/pet/home 等已注册场景时，后台预加载对应知识库；光线剧变时静默调后端刷新方案
- 性能预算：<50ms/帧，仅在取景态运行，电量低于 20% 自动降频

**第 4 层 · 拍摄后闭环**

- 拍完底部出现缩略图 → 点开"成片对比方案"视图
- 上半屏：实拍照片；下半屏：方案 result 预期 + subject/shooter 要点对照
- 三个动作：**一键修图**（进后期，quick_edit 已预置）/ **重拍这个方案**（回相机，叠加层还在）/ **换方案**

#### 5.2.2 手动控制

底部控件条（参考 Halide + Obscura 的手势逻辑，但视觉奶油化）：

- **左侧竖向**：EV 补偿滑杆（暖金刻度）
- **右侧竖向**：焦段滚轮（0.5× / 1× / 2× / 3×，推荐焦段金色吸附点）
- **底部横条**：白平衡 → ISO → 快门 → 对焦 四级手动，长按数值锁定
- **对焦**：点屏幕对焦 + 手动对焦环（对焦峰值留 v2.0）
- **快门**：大圆形，外圈暖金进度环（倒计时自拍时）

#### 5.2.3 相机模式（顶部切换）

拍照（默认）/ 人像（深度）/ 夜景（长曝光引导）/ ProRAW（仅 Pro 机型）。v1.0 不做视频。

### 5.3 模块 C：非破坏性后期编辑

#### 5.3.1 编辑栈数据结构

每张照片存一个 edit stack JSON，原图不动，导出时烘焙：

```json
{
  "original": "IMG_20260811.dng",
  "format": "proraw" | "heic" | "jpeg",
  "stack": [
    { "op": "exposure", "value": 0.7 },
    { "op": "temperature", "value": -8 },
    { "op": "contrast", "value": 12 },
    { "op": "preset", "id": "style-summer-glow", "strength": 0.8 }
  ],
  "crop": { "rotation": 0, "aspect": "4:5" },
  "version": 1
}
```

方案的 `quick_edit.steps[]` 天然映射为这个 stack 的初始值——用户进后期时滑块已摆好，微调即可。

#### 5.3.2 调节面板分期

**一期（v1.0，对标 Snapseed/系统相册+）**：

曝光、对比度、高光、阴影、白点、黑点、亮度、色温、色调、饱和度、自然饱和度、鲜明度、裁剪旋转、15 个胶片风格预设（来自 17 个 style-recipes 里成熟的几组）。

**二期（v1.5）**：HSL 分通道、曲线、清晰度、锐化、降噪、暗角、颗粒、基于深度图的人像虚化/光圈。

**三期（v2.0）**：ProRAW 全功能、局部调整、蒙版、AI 智能调色建议。

#### 5.3.3 引擎实现

- **一期全部用 Skia ColorMatrix + ImageFilter**：曝光/对比/色温/饱和都是标准 color matrix，高光阴影用层级 shader。跨端一致，GPU 加速。
- **ProRAW**：iOS 走原生模块 Core Image `CIRAWFilter` 解码 → 位图 → Skia 管线；Android v1.0 不开放 RAW 编辑（仅拍摄存储）。
- **预设**：39 个知识库风格中，选 15 个有完整后期参数的（style-recipes/）做成一键预设，强度可调（0-100%）。
- **导出**：烘焙为 JPEG（社交）/ HEIC（高质），保留 EXIF，可选带/不带水印。

#### 5.3.4 编辑界面布局

- 上半屏：照片预览（暖调深炭底 #161412，让照片突出）
- 中部：横向滑条（当前参数），数值在滑条上方暖金色显示
- 底部：工具 Tab（调节 / 预设 / 裁剪），Tab 下是对应参数宫格或滑条
- 右下角"对比"长按看原图，右上角"撤销/重做"

### 5.4 模块 D：图生图提示词（保持现状，优化跳转）

- 方案里的 `img_gen_prompt` 在成片对比页有"✨ AI 改图"入口
- 点击：复制提示词到剪贴板 + 一键跳转豆包 APP（URL scheme），提示用户"已复制，去豆包粘贴即可"
- 不直接调 Seedream API，零成本、零合规风险
- `img_additions`（无中生有项）以小标签展示，让用户知道 AI 会改什么

### 5.5 模块 E：作品库与数据飞轮

- 本地作品库按日期/场景/方案分组，显示缩略图 + 所用方案名 + 风格
- 每次拍摄回流：`session_id, direction_id, plan_index, shot_focal, ev, iso, final_edit_stack, feedback(👍👎)`
- 回流数据进入现有 `usage_sessions` / `plan_feedback` 表，新增 `shot_params` 表
- 管理后台（现有 admin.html）新增"实拍参数"面板，看用户实际用了什么焦段/EV，反哺方案的 gear 字段准确性

## 6. UI/UX 设计系统 · 奶油胶片杂志

> 一个设计观点：**温暖但不幼稚，专业但不冰冷，有纸感和胶片颗粒感**。
> 反 AI slop：拒绝紫粉渐变、模糊玻璃卡、emoji 当图标、过度圆角到没有边界。

| 英文标题 | **Playfair Display** SemiBold | 与宋体气质一致，杂志衬线 |
| 正文/UI | **苹方** PingFang SC（iOS 系统） | 清晰、不抢标题 |
| 数字/参数 | **SF Pro Display** / 系统等宽 | EV/ISO/焦段数字用等宽数字，跳动时不晃 |

字号阶梯：大标题 28/34px（宋体）、卡片标题 20px、正文 15px、小字 12-13px、标签 10-11px（字距 +0.5px）。

#### 形状与间距

- 圆角：卡片 22px、按钮 16px、输入框 14px、小标签 10px（**不是全站一个圆角**，层级分明）
- 间距：8 的倍数（4/8/12/16/24/32/48），内容页留白足（卡片内边距 20-24px）
- 描边：1px `--line`，极淡，靠柔阴影分卡片层级
- 阴影：柔而不散 `0 8px 30px rgba(28,25,23,0.06)`，无重投影

#### 质感

- 奶油底可加极淡纸纹噪声（opacity 3%），不刻意
- 按钮按下去有轻微 scale(0.97) + 亮度变化，150ms
- 方向卡/方案卡用 magazine 式排版：宋体大标题 + 英文小字标注 + 留白

#### 动效

- 时长 150-300ms，ease-out / back.out(1.3) 用于卡片入场
- 方案切换时叠加层元素用 stagger（构图框先变、参数刻度跟进），60ms 错峰
- 尊重 `prefers-reduced-motion` / iOS "减弱动态效果"
- 震动：焦段吸附（light）、日落时机（medium 一次）、拍摄完成（轻触反馈）——不滥用

### 6.2 导航结构

底部 Tab 4 个（≤5 规范）：

1. **首页**（拍）：今天的光线 + "开始拍"大按钮 + 最近方案
2. **灵感**：风格库/场景教程/历史方案（v1.0 可先放 39 风格 + 知识库精选）
3. **作品**：本地作品库
4. **我的**：配额/设置/反馈/登录

相机是**全屏模态**，从首页大按钮或作品页相机图标进入，不在 Tab 里。

后期编辑器是相机/作品库推入的全屏页。

### 6.4 触控与无障碍规范（UI/UX Pro Max 硬指标）

- 所有可点元素 **≥44×44px**，相邻间距 ≥8px
- 小图标按钮加 `hitSlop={{top:10,bottom:10,left:10,right:10}}`
- 150-300ms 状态过渡，不用 0ms 瞬变
- 正文 ≥15px，文字对比度 ≥4.5:1（奶油底上焙茶褐对比度达标）
- 对焦框/引导图形不只靠颜色传达信息，配合形状（框=站位、线=构图、刻度=参数）
- 支持系统动态字号（最大到 AX5 不破版）
- 支持 VoiceOver：方案卡四段朗读为"被拍摄者：…；摄影师：…"
- 震动反馈不滥用（见 6.1）
- 返回键可预测，不意外退出；模态有明确关闭 + 下拉关闭

## 7. 数据模型与 API

### 7.1 本地 SQLite（新增表，与现有 schema 对齐）

- `app_sessions`：同步自服务器的会话（方向/方案 JSON 缓存）
- `app_shots`：每张实拍（uri、session_id、direction_id、plan_index、focal、ev、iso、wb、timestamp）
- `app_edit_stacks`：每图的编辑栈 JSON
- `app_presets_cache`：39 风格预设缓存
- `app_sync_queue`：待回流数据（离线拍摄后联网同步）

### 7.2 后端新增（详见 5.1）

JWT 鉴权中间件保护 `/app/*`；现有 `/analyze/*` 改为接受 JWT 或现有 IP 配额双轨（Web 端不破坏）。

大文件（RAW 20-50MB）走分片上传：`/app/session/init` → `/app/session/chunk` → `/app/session/complete`。
